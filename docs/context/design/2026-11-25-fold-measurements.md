### 접기 계획 기준의 판정과 남은 일 (2026-11-27)

### PR #40 리뷰 반영 측정 (2026-11-27)

PR #40 리뷰의 4·6·8번을 이 머신에서 쟀습니다. 기준선은 리뷰 반영 전 `59c72f8`, 최종은 교차 리뷰 게이트(`cross_review.py`), 리뷰어의 확인 기준 실행, 0단계 판정 스크립트를 넣은 판입니다. 사례마다 1~2회라 잡음이 큽니다.

- **환경 제약:** 이 머신(WSL, root)의 eval Bash 샌드박스는 작업 폴더, `.git`, `$TMPDIR`를 읽기 전용으로 둡니다. Bash로 쓰는 e2e 사례는 브랜치 만들기, `protected_paths.py init`, 저장소 밖 brief 초안 쓰기에서 멈춥니다. 그래서 e2e 사례는 끝까지 돌지 못했습니다. `~/.docker/contexts` 심볼릭 링크도 Bash eval을 막아, 측정하는 동안 일반 폴더로 바꿨다가 되돌렸습니다.
- **4번 `set-ticket-loaded`:** 기준선 `e2e-spec-three-tickets` 1회에서 원인이 드러났습니다. 상태 파일 `## 결정`에 "4단계: 건너뜀. 남은 일(함수 3개와 테스트 1개)이 새 컨텍스트 창 하나로 끝나는 크기라 티켓을 나누지 않는다"가 적혔습니다. 스킬을 불러오지 못한 것이 아니라, 3단계의 크기 기준이 이 사례의 작은 기획서에서 4단계를 건너뛰게 한 것입니다. 사례는 티켓 3개를 기대합니다. 고친 것: run-flow 3단계에 "사용자가 티켓으로 나누라고 했으면 크기와 상관없이 4단계"를 더하고, 사례 프롬프트에 티켓으로 나눠 진행한다는 답을 넣었습니다. 최종 판 1회는 위 환경 제약으로 3단계(초안 임시 파일)에서 멈춰 이 수정을 확인하지 못했습니다.

## 다시 돌리는 방법

1. Bash를 안전하게 격리할 수 있는 환경을 씁니다. 기준선과 최종을 각각 detached worktree에 만들고, 기준선의 run-ticket 및 e2e 사례를 최종 사례와 맞춥니다. 두 임시 매니페스트의 `skills` 배열에 `./skills/in-progress/`를 추가합니다. 배포 매니페스트에는 이 변경을 넣지 않습니다. Python은 샌드박스 안에서 동작하는 경로를 씁니다.
2. 아래 예시처럼 사례를 지정하고 각 기록을 별도 JSON으로 저장합니다. `--case`를 여러 번 주면 마지막 값만 남습니다. 트리거는 `--eval-dir evals-trigger/run-ticket`으로 돌리고 Bash를 열지 않습니다.

```bash
claude plugin eval . --scaffold --allow-tools Bash Write Edit WebSearch WebFetch \
  --ablation none --no-publish --trust-plugin --runs 1 --keep-temp \
  --case 'e2e-ambiguous-framing' --json result.json
claude plugin eval . --scaffold --allow-tools Bash Write Edit WebSearch WebFetch \
  --ablation none --no-publish --trust-plugin --runs 1 \
  --eval-dir evals/run-ticket --json run-ticket.json
```

3. `e2e-spec-to-pr`는 `e2e-spec-three-tickets`가 결과를 남긴 경우에만 따로 돌립니다. 후자의 `--keep-temp` 작업 트리 경로를 `E2E_E2_WORKTREE`로 넘깁니다. 중단된 E2의 빈 작업 트리나 독립 E3 점수로 이 결과를 대신하지 않습니다.
4. `cases[].arms.with[]`의 `error`, 채점기별 판정, 턴·비용·시간을 사례별로 비교합니다. `tracePath`의 trace에서 입출력 토큰 합계와 컨텍스트 압축이 일어났는지도 사례별로 적습니다. 비용이나 시간이 늘면 어느 사례에서 늘었는지 이 값으로 가립니다. E4·E5·E8·E10의 `.git/e2e-judge/` 판정은 별도로 확인합니다. 원시 실행 디렉터리에는 에이전트가 만든 파일이 있으므로 그 안에서 호스트 도구를 직접 실행하지 말고, 검토한 판정 스크립트만 격리된 환경에서 실행합니다.
