# check-guidelines

레포에 이미 있는 규칙으로 코드를 검사하고, 규칙을 어긴 곳을 규칙별로 묶은 보고서를 받을 수 있습니다. 규칙은 `.claude/rules/` 규칙 파일, CLAUDE.md/AGENTS.md, 린터·포매터 설정에서 모읍니다. 보고서에서 고칠 위반의 번호를 고르면 그 위반만 고친 뒤 같은 규칙으로 다시 검사해 확인합니다.

| 항목 | 값 |
|---|---|
| 버킷 | engineering |
| 호출 방식 | Model-invoked |
| 호출 | `/gongbang:check-guidelines [all \| diff \| branch \| 경로]` |
| 원문 | [SKILL.md](../../skills/engineering/check-guidelines/SKILL.md) |

**목차**: [언제 쓰나](#언제-쓰나) · [준비물](#준비물) · [진행 과정](#진행-과정) · [결과물](#결과물) · [커스텀](#커스텀) · [함께 쓰는 스킬](#함께-쓰는-스킬)

## 언제 쓰나

- 코드가 컨벤션이나 팀 규칙을 지키는지 점검할 때
- 커밋이나 PR 전에 변경분에서 규칙 위반을 찾을 때

"규칙 지키는지 검사해 줘", "PR 올리기 전에 컨벤션 위반 봐 줘"처럼 요청하면 이름을 입력하지 않아도 Claude가 이 스킬을 고를 수 있습니다.

규칙을 새로 만들거나 바꾸려면 set-guidelines를 쓰세요. 버그나 성능을 보는 일반 코드 리뷰에는 이 스킬을 쓰지 않습니다.

## 준비물

- 규칙 파일(`.claude/rules/`), CLAUDE.md/AGENTS.md, 린터·포매터 설정 중 하나 이상이 레포에 있어야 합니다. 하나도 없으면 검사하지 않고, set-guidelines로 규칙부터 만들라고 안내합니다.
- 린터·포매터는 설치된 것만 실행합니다. 설치되지 않은 도구는 설치하지 않고 건너뛰며, 보고서 요약의 "검사 못 함"에 적습니다.

## 진행 과정

1. **검사 범위 정하기**: 인자로 범위를 받습니다. 인자가 없으면 아래 넷 중 하나를 고르게 합니다.

   | 범위 | 검사할 파일 |
   |---|---|
   | `all` | 레포 전체 |
   | `diff` | 커밋하지 않은 변경 전부. staged, unstaged, 새 파일(untracked)을 모두 넣습니다 |
   | `branch` | origin의 기본 브랜치에서 갈라진 뒤 바뀐 파일. 기본 브랜치를 찾지 못하면 기준 브랜치를 묻습니다 |
   | 경로 | 지정한 파일이나 디렉터리 |

2. **규칙 모으기**: 규칙 파일, CLAUDE.md/AGENTS.md, 린터·포매터 설정을 찾아 읽습니다. `paths`가 있는 규칙 파일은 그 패턴에 맞는 파일에만 적용하고, `paths`가 없는 규칙 파일과 CLAUDE.md/AGENTS.md는 검사할 파일 전부에 적용합니다.
3. **검사**: 규칙 파일과 CLAUDE.md/AGENTS.md의 규칙은 파일을 읽어 판단합니다. 린터·포매터는 검사할 파일에 실행하고, 그 결과를 위반에 넣습니다.

   검사할 파일이 100개를 넘으면 오래 걸리고 컨텍스트를 많이 쓴다고 경고합니다. 파일 수와 최상위 디렉터리별로 나눈 구역을 보여 주고, 승인하면 구역을 차례로 검사해 구역마다 결과를 보고서에 바로 기록합니다.
4. **보고**: 보고서를 보여 준 뒤 고칠지 묻습니다. 고치려면 고칠 위반을 번호로 고르세요.
5. **고치기와 재검사**: 고른 위반만 고치고, 고친 파일을 같은 규칙으로 다시 검사합니다. 고른 위반이 남아 있으면 다시 고치고 검사합니다. 끝나면 고친 위반과 재검사 결과를 알려 줍니다.

## 결과물

`templates/report.md` 양식의 규칙 검사 보고서를 받습니다. 보고서는 합니다체로 씁니다.

맨 위에는 검사한 범위와 파일 수, 위반·애매함·규칙 충돌의 건수를 두 문장 안으로 요약하고, 범위·적용한 규칙·검사 못 함을 표로 정리합니다. "검사 못 함" 행은 건너뛴 도구가 있을 때만 넣습니다. 그 아래 절은 다음 셋이고, 0건인 절은 만들지 않습니다.

- **위반**: 규칙별로 묶어 규칙 위치를 적고, 위반마다 위치, 현재 코드, 고치는 방법을 적습니다. 번호는 보고서 전체에서 이어 매깁니다.
- **애매함**: 위반인지 판단하기 어려운 곳과 그 이유를 적습니다. 문제없는 코드를 고치게 되지 않도록 위반으로 세지 않습니다.
- **규칙 충돌**: 서로 부딪치는 규칙과 각 위치, 규칙을 어떻게 고칠지 제안을 적습니다. 어느 규칙이 맞는지는 팀이 정합니다.

## 커스텀

| 바꾸고 싶은 것 | 고칠 파일 |
|---|---|
| 보고서 양식과 문체 | `templates/report.md` |
| 검사 범위 선택지 | SKILL.md의 "1. 검사 범위 정하기" |
| 구역으로 나눠 검사하는 기준(검사할 파일 100개) | SKILL.md의 "3. 검사" |

검사 기준은 레포의 규칙 파일, CLAUDE.md/AGENTS.md, 린터·포매터 설정에서 옵니다. 기준을 바꾸려면 그 파일을 고치세요. 스킬을 복사해서 고치는 방법은 [커스텀 가이드](../customization.md)를 보세요.

## 함께 쓰는 스킬

- **set-guidelines**: 규칙이 없으면 먼저 실행해 규칙을 만드세요.
- **run-ticket**: 5단계 리뷰에서 이 스킬을 불러, 바꾼 파일 경로를 범위로 검사하고 보고까지만 받습니다. 지적 중 티켓 범위 안의 것은 run-ticket이 고칩니다.
