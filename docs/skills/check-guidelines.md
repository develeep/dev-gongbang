# check-guidelines

레포에 있는 규칙으로 코드를 검사한다. `.claude/rules/` 규칙 파일, CLAUDE.md/AGENTS.md, 린터·포매터 설정에서 규칙을 모아 위반을 규칙별로 보고한다. 고를 위반을 번호로 알려 주면 그것만 고친 뒤 다시 검사해 확인한다.

| 항목 | 값 |
|---|---|
| 버킷 | engineering |
| 호출 방식 | Model-invoked |
| 호출 | `/gongbang:check-guidelines [all \| diff \| branch \| 경로]` |
| 원문 | [SKILL.md](../../skills/engineering/check-guidelines/SKILL.md) |

**목차**: [언제 쓰나](#언제-쓰나) · [준비물](#준비물) · [진행 과정](#진행-과정) · [결과물](#결과물) · [커스텀](#커스텀) · [함께 쓰는 스킬](#함께-쓰는-스킬)

## 언제 쓰나

- 코드가 컨벤션이나 팀 규칙을 지키는지 점검한다.
- 커밋이나 PR 전에 변경분의 규칙 위반을 찾는다.

"규칙 지키는지 검사해 줘", "PR 올리기 전에 컨벤션 위반 봐 줘"처럼 요청하면 이름을 입력하지 않아도 Claude가 이 스킬을 고를 수 있다.

규칙을 새로 만들거나 바꾸는 일은 set-guidelines가 맡는다. 버그나 성능을 보는 일반 코드 리뷰에는 쓰지 않는다.

## 준비물

- 규칙 파일, CLAUDE.md/AGENTS.md, 린터·포매터 설정 중 하나 이상. 하나도 없으면 검사하지 않고 set-guidelines부터 실행하라고 안내한다.
- 린터·포매터는 설치된 것만 실행한다. 설치되지 않은 도구는 건너뛰고 보고서의 "검사 못 함"에 적는다.

## 진행 과정

1. 검사 범위를 정한다. 인자가 없으면 고르게 한다.
   - `all`: 레포 전체
   - `diff`: 커밋하지 않은 변경 전부(staged, unstaged, untracked)
   - `branch`: origin 기본 브랜치에서 갈라진 뒤 바뀐 파일
   - 경로: 지정한 파일이나 디렉터리
2. 규칙을 모은다. `paths`가 있는 규칙 파일은 그 패턴에 맞는 파일에만 적용한다.
3. 검사한다. 대상 파일이 100개를 넘으면 경고하고, 최상위 디렉터리별 구역을 보여 준 뒤 승인받으면 구역마다 서브에이전트로 나눠 검사한다.
4. 보고하고, 고칠 위반을 번호로 고르게 한다.
5. 고른 위반만 고치고 같은 규칙으로 다시 검사한다.

## 결과물

규칙 검사 보고서. 0건인 절은 만들지 않는다.

- **위반**: 규칙별로 묶고, 위치·현재 코드·고치는 방법을 적는다. 번호는 보고서 전체에서 이어 매긴다.
- **애매함**: 위반인지 판단하기 어려운 곳. 위반으로 세지 않는다.
- **규칙 충돌**: 서로 부딪치는 규칙과 위치, 규칙을 고칠 제안. 어느 규칙이 맞는지는 팀이 정한다.

## 커스텀

| 바꾸고 싶은 것 | 고칠 파일 |
|---|---|
| 보고서 양식과 문체 | `templates/report.md` |
| 검사 범위 선택지, 서브에이전트로 나누는 기준(100개) | SKILL.md의 1단계와 3단계 |

검사 기준 자체는 스킬이 아니라 레포의 규칙 파일, CLAUDE.md/AGENTS.md, 린터·포매터 설정에서 온다. 기준을 바꾸려면 그 파일을 고친다. 복사해서 고치는 방법은 [커스텀 가이드](../customization.md)를 본다.

## 함께 쓰는 스킬

- **set-guidelines**: 규칙이 없을 때 먼저 실행해 규칙을 만든다.
