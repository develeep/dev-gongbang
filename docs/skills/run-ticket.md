# run-ticket

set-ticket이 만든 티켓 하나를 새 세션에서 구현하고 리뷰한 뒤, 티켓 상태와 brief 체크박스를 갱신합니다. brief를 만든 대화 없이 brief, 티켓, 앞 티켓의 완료 기록만 근거로 삼습니다. 커밋은 하지 않습니다.

> 만드는 중인 스킬입니다. `gongbang-dev`를 설치해야 쓸 수 있고, 동작이 바뀔 수 있습니다.

| 버킷 | in-progress |
| 호출 방식 | User-invoked |
| 호출 | `/gongbang:run-ticket [티켓·brief 경로, 이슈 번호·URL] [여러 티켓이면 범위]` |
| 원문 | [SKILL.md](../../skills/in-progress/run-ticket/SKILL.md) |

## 언제 쓰나

- set-ticket으로 나눈 티켓을 하나씩 실행할 때
- 티켓으로 나누지 않은 작은 brief를 실행할 때. 이때는 brief 전체를 티켓 하나로 봅니다.
- "남은 티켓 전부"처럼 여러 티켓을 차례로 실행할 때

## 준비물

- set-brief·set-ticket으로 만든 brief와 티켓
- GitHub 티켓이면 `gh` CLI가 로그인돼 있어야 합니다.
- 작업 트리에 brief·티켓 밖의 변경이 있으면 커밋하고 진행할지 묻습니다. 그대로 진행하면 리뷰에 이전 변경이 섞입니다.

## 진행 과정

1. 티켓을 고릅니다. 인자가 없으면 끝나지 않은 티켓이 남은 brief 중 가장 최근 것에서, 막힘 관계가 풀린 티켓 중 번호가 가장 앞선 것을 고릅니다.
2. 티켓과 brief 전문, 같은 brief의 끝난 티켓의 완료 기록, 레포의 CLAUDE.md·AGENTS.md를 읽습니다.
3. "만들 것"을 구현합니다. 티켓 범위 밖의 문제는 고치지 않고 보고에 남깁니다.
4. 완료 기준을 하나씩 명령이나 관찰로 확인합니다. 통과하지 못하면 고치고, 고칠 수 없으면 멈추고 보고합니다.
5. 리뷰합니다. 레포 규칙이 지정한 리뷰 스킬, `code-review` 스킬, 직접 리뷰 순서로 처음 맞는 방법을 씁니다.
6. 티켓 상태를 done으로 바꾸거나 이슈를 닫고, brief 체크박스를 갱신하고, 완료 기록을 남깁니다. 마지막 티켓이면 brief의 "확인 기준"을 실행하고 brief를 닫습니다.

티켓과 레포 규칙이 충돌하면 진행하기 전에 묻습니다. 우선순위는 티켓의 "하면 안 되는 것"·"작업 경계", 레포 규칙, 스킬의 기본 동작 순입니다.

### 여러 티켓 실행

번호 범위나 "남은 티켓 전부"를 요청하면 티켓마다 서브에이전트를 하나씩 차례로 띄웁니다. 같은 작업 트리를 고치므로 병렬로 띄우지 않습니다. 완료 기준을 통과하지 못한 티켓이 나오면 멈추고, 모두 끝나면 전체 변경을 한 번 리뷰합니다.

## 결과물

- 구현한 코드 변경 (커밋하지 않음)
- 티켓에 붙는 완료 기록: 완료일, 커밋 안 함과 작업 시작 HEAD, 바꾼 파일. 다른 티켓이 쓸 결과는 `## 산출물`에 남깁니다.
- 보고: 끝낸 티켓, 완료 기준 결과, 바꾼 파일, 산출물 위치, 고치지 않은 리뷰 지적, 다음 티켓

| 바꾸고 싶은 것 | 고칠 곳 |
|---|---|
| 티켓 고르는 규칙 | SKILL.md의 "1. 티켓 고르기" |
| 리뷰 방법의 우선순위 | SKILL.md의 "5. 리뷰" |
| 완료 기록 형식 | SKILL.md의 "6. 완료 기록" |

커밋하지 않는 동작은 핵심 규칙입니다. 레포 규칙이 커밋을 요구해도 사용자에게 맡깁니다. 복사해서 고치는 방법은 [커스텀 가이드](../customization.md)를 보세요.

## 함께 쓰는 스킬

- **set-brief**, **set-ticket**: 실행할 brief와 티켓을 만듭니다.
- **code-review** 스킬이 설치돼 있으면 5단계 리뷰에 씁니다.
