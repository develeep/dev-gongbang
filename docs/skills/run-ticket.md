# run-ticket

set-ticket이 만든 티켓 하나를 구현하고 리뷰한 뒤, 티켓 상태와 brief 체크박스를 갱신합니다. run-flow에서 이어 실행하면 brief를 만든 대화가 같은 세션에 남아 있을 수 있지만, 그래도 brief, 티켓, 앞 티켓의 완료 기록만 근거로 삼습니다. 구현, 완료 기준 확인, 코드 리뷰, 규칙 검사는 이 세션이 직접 하고, 새 컨텍스트에 맡기는 것은 다른 회사 모델의 교차 리뷰 하나입니다. 커밋은 하지 않습니다. 여러 티켓을 요청하면 이 세션이 차례로 직접 실행합니다. 병렬 실행은 사용자가 고를 때만 쓰는 선택 경로입니다. 함께 시작할 수 있는 티켓이 둘 이상이고 통합 브랜치를 공유하는 티켓이 없으며 사용자나 레포·에이전트 규칙이 쓸 수 있는 워커 도구 절차를 지정해 두었으면, 그 절차로 티켓마다 워커를 띄워 worktree를 나눠 병렬로 실행하고 이때만 티켓 브랜치에 커밋해 머지합니다. 쓸 수 있는 절차가 없으면 차례로 실행합니다.

> 만드는 중인 스킬입니다. `gongbang-dev`를 설치해야 쓸 수 있고, 동작이 바뀔 수 있습니다.

## 언제 쓰나

- set-ticket으로 나눈 티켓을 하나씩 실행할 때
- 티켓으로 나누지 않은 작은 brief를 실행할 때. 이때는 brief 전체를 티켓 하나로 봅니다.
- "남은 티켓 전부"처럼 여러 티켓을 한 번에 실행할 때. 기본은 이 세션이 차례로 직접 실행하는 것입니다. 사용자가 병렬 실행을 골랐고(워커 도구 절차를 지정했거나 규칙에 등록해 둔 것), 그 절차를 쓸 수 있고, 함께 시작할 수 있는 티켓이 둘 이상이며, 통합 브랜치를 공유하는 티켓이 없으면 병렬로 실행합니다.

## 준비물

- set-brief·set-ticket으로 만든 brief와 티켓
- GitHub 티켓이면 `gh` CLI가 로그인돼 있어야 합니다.
- 작업 트리에 brief·티켓 밖의 변경이 있으면 커밋하고 진행할지 묻습니다. 그대로 진행하면 리뷰에 이전 변경이 섞입니다. 끝난 티켓의 "바꾼 파일"에 없는 변경은 끊긴 티켓의 미완성 변경일 수 있어 따로 보여 주고, 이번 티켓이 건드리지 않는 파일이어도 되돌릴지 이어서 쓸지 묻습니다.
- 병렬 실행은 선택 기능입니다. 사용자가 고르지 않으면 이 세션이 티켓을 차례로 직접 실행합니다. 여러 티켓을 병렬로 실행하려면 워커 도구 절차가 지정돼 있어야 합니다. 워커 도구 절차는 워커를 띄우는 도구 하나로 워커를 만들고, 기다리고, 정리하는 방법을 적은 문서입니다. 아래 순서로 절차를 보고, 그 절차의 사용 조건을 만족하는 첫 절차를 씁니다. 지정된 절차가 없거나 모두 쓸 수 없으면 차례로 실행합니다.
  1. 사용자나 부른 쪽이 정한 도구의 절차
  2. 레포·에이전트 규칙(CLAUDE.md, AGENTS.md)이 지정한 절차. 여럿이면 규칙에 적힌 순서로 봅니다.
- 선택 설정 예: [Orca 오케스트레이션 설정](../orca-orchestration.md), [Paseo 오케스트레이션 설정](../paseo-orchestration.md). 각 문서에 도구 설치와 절차를 규칙 파일에 등록하는 방법이 있습니다.
- 교차 리뷰는 이번 변경을 구현한 모델과 다른 회사의 모델이 하는 읽기 전용 리뷰입니다. 구현한 모델은 이 세션의 모델이고, 병렬 실행에서는 그 티켓을 구현한 워커의 모델입니다. 다른 회사 모델을 쓰려면 실행할 때 지정하거나, 교차 리뷰를 맡을 에이전트나 모델을 레포·에이전트 규칙, 하네스 설정, 저장된 프로필에 적어 두거나(예: [omp 멀티에이전트 설정](../omp-orchestration.md)), 교차 리뷰 워커를 정해 둔 워커 도구 절차를 지정합니다. 적어 둔 것이 없으면 이 세션에서 쓸 수 있는 모델을 조회해 고릅니다. 다른 회사 모델을 쓸 수 없어도 교차 리뷰를 건너뛰지 않습니다. 같은 회사 모델의 새 컨텍스트 리뷰로 대체하고, 대체했다는 것과 수행한 모델을 완료 기록에 적은 뒤 계속합니다. 자세한 순서는 아래 "교차 리뷰"에 있습니다.

## 진행 과정

1. 티켓을 고릅니다. 인자가 없으면 끝나지 않은 티켓이 남은 brief 중 가장 최근 것에서, 막힘 관계가 풀린 티켓 중 번호가 가장 앞선 것을 고릅니다.
2. 티켓과 brief 전문, 같은 brief의 끝난 티켓의 완료 기록, 레포의 CLAUDE.md·AGENTS.md를 읽습니다.
3. "만들 것"을 이 세션이 직접 구현합니다. 구현을 서브에이전트나 다른 에이전트에 맡기지 않습니다. 예외는 병렬 실행의 워커뿐입니다. 티켓 범위 밖의 문제는 고치지 않고 보고에 남깁니다.
4. 완료 기준을 하나씩 명령이나 관찰로 확인합니다. 화면에서 봐야 하는 기준도 이 세션이 직접 확인합니다. 브라우저를 다루거나 화면을 캡처할 수단이 있으면 화면을 열어 보고 근거를 남기고, 확인하지 못한 항목은 통과로 치지 않고 완료 기록의 "확인 못 한 것"에 적습니다. 통과하지 못한 기준은 같은 세션에서 원인을 정리하고 고쳐 다시 확인합니다. 다른 에이전트에 다시 맡기거나 올리지 않습니다. 최초 시도를 포함해 3회째에도 통과하지 못하면 티켓 상태를 바꾸지 않고 멈추고, 통과하지 못한 기준, 시도 횟수, 실패 원인을 보고한 뒤 티켓을 다시 나눌지 묻습니다. run-flow가 불렀으면 같은 내용을 상태 파일의 `- 멈춘 이유:`에 적습니다. 더 강한 모델이 필요하면 세션 모델을 바꿔 다시 실행할 수 있습니다.
5. 리뷰합니다. 이 세션이 코드 리뷰(레포 규칙이 지정한 리뷰 스킬, `code-review` 스킬, 직접 리뷰 순서로 처음 맞는 방법)와 check-guidelines 규칙 검사를 차례로 직접 하고, 그 지적을 고친 뒤 교차 리뷰를 한 번 부릅니다. 리뷰 스킬이 서브에이전트로 하위 리뷰를 띄우라고 해도 띄우지 않고 이 세션이 차례로 직접 봅니다. 그렇게 실행할 수 없는 스킬이면 쓰지 않고 직접 리뷰한 뒤 보고에 적습니다. 보안 리뷰는 따로 부르지 않고, 변경이 인증, 권한, 결제, 개인정보를 다루면 교차 리뷰의 기준에 보안을 더합니다. 교차 리뷰의 지적을 모두 검증한 뒤에 완료 기록으로 넘어갑니다. 교차 리뷰를 하지 않고 이 단계를 끝내는 경로는 없습니다.
6. run-flow가 보호 경로 검사를 넘겼으면 먼저 시작 HEAD의 테스트와 판정용 사례가 바뀌거나 지워지지 않았는지 검사합니다. 셸로 바꾼 것도 잡습니다. 실패하면 티켓을 수락하지 않고 바뀐 파일을 보여 준 뒤 멈추고, 통과하면 이 티켓이 새로 만든 테스트를 보호 목록에 더합니다. 그다음 티켓 상태를 done으로 바꾸거나 이슈를 닫고, brief 체크박스를 갱신하고, 완료 기록을 남깁니다. 레포 규칙이나 run-flow 상태 파일이 완료 표시를 다른 값으로 정했으면 done 대신 그 값을 씁니다. 마지막 티켓이면 brief의 "확인 기준"을 실행하고 brief를 닫습니다. 여러 티켓 실행에서는 이 일을 통합 리뷰 뒤에 한 번 합니다.

티켓과 레포 규칙이 충돌하면 진행하기 전에 묻습니다. 우선순위는 티켓의 "하면 안 되는 것"·"작업 경계", 레포 규칙, 스킬의 기본 동작 순입니다.

### 교차 리뷰

이 세션이 5단계에서 한 번 부르고, 결과를 받아 같은 대화에서 이어 갑니다. 리뷰어는 사용자와 대화하지 않고 다음 단계를 정하지 않습니다.

- **넘기는 것**: 리뷰할 diff 범위(작업 시작 HEAD 기준), brief 전문(티켓 하나를 리뷰하면 그 티켓 전문도), 볼 기준 목록입니다. 기준은 버그, 티켓의 "하면 안 되는 것"·"작업 경계" 위반과 레포 규칙 위반이고, 변경이 인증, 권한, 결제, 개인정보를 다루면 보안을 더합니다. 비밀값과 원문 로그는 넘기지 않습니다.
- **권한**: 읽기 전용입니다. 리뷰어는 파일을 고치거나 커밋하지 않고 저장소 밖에도 쓰지 않습니다. 이 세션은 부르기 직전과 결과를 받은 직후의 코드 지문(HEAD 해시와 작업 트리의 tree 해시)을 비교합니다. tree 해시를 구하지 못하면 멈추지 않고 `git status --porcelain`과 `git diff HEAD`의 출력으로 비교하고, 그렇게 했다고 보고에 적습니다. 달라졌으면 그 리뷰 결과를 쓰지 않고, 바뀐 것을 보여 준 뒤 다음 수단에 다시 맡깁니다.
- **돌려받는 것**: 지적 목록과 수행한 모델 이름만 받습니다. 지적마다 어느 기준의 지적인지, 심각도, 파일과 줄, 근거(재현 명령이나 코드·규칙 원문), 고칠 방법이 있습니다. 요약, 총평, 수정 diff는 받지 않습니다.
- **지적 검증**: 이 세션이 지적을 하나씩 재현하거나 코드·규칙 원문과 대조해 수용, 기각(사유), 범위 밖 가운데 하나로 적습니다. 수용한 지적은 고친 뒤 완료 기준과 검증 명령을 다시 확인합니다. 지적이 없다는 보고는 수락의 근거가 아니라 입력 하나로 봅니다.
- **모델과 수단**: 모델을 정해 두지 않습니다. 조건은 구현한 모델과 다른 회사라는 것 하나이고, 부를 때마다 다음 순서에서 처음 되는 것을 씁니다.
  1. 사용자나 부른 쪽이 이번 실행에서 지정한 모델이나 수단
  2. 사용자 설정에 적힌 교차 리뷰 수단: 레포·에이전트 규칙 파일, 하네스 설정, 저장된 에이전트 프로필이 정해 둔 에이전트나 모델, 지정되거나 등록된 워커 도구 절차의 "교차 리뷰 워커"
  3. 환경 조회: 이 세션에서 쓸 수 있는 provider, 모델, 에이전트 목록에서 다른 회사 모델을 고르고, 무엇을 골랐는지 알립니다
  4. 다른 회사 모델을 쓸 수 없으면 같은 회사 모델의 새 컨텍스트 리뷰로 대체합니다. 넘기는 것, 권한, 돌려받는 것, 지적 검증은 같습니다. 띄울 때 모델을 정할 수 있으면 정해서 띄워, 기록에 수행한 모델 이름을 적을 수 있게 합니다

  응답이 없거나 결과를 읽을 수 없으면 다음 수단에 다시 맡깁니다. 독립 여부는 계획한 모델이 아니라 실제로 수행한 모델로 판정합니다. 수행한 모델이 구현한 모델과 같은 회사였으면 다음 수단에 다시 맡기고, 남은 수단이 4번뿐이면 그 리뷰를 4번의 대체로 칩니다. 새 컨텍스트를 하나도 띄울 수 없으면 이 세션의 자기 리뷰로 대체합니다. 자기 리뷰는 같은 회사 모델의 새 컨텍스트 리뷰보다 약하므로 표시를 따로 씁니다.
- **기록**: 완료 기록의 `- 교차 리뷰:` 줄에 아래 셋 가운데 하나를 적습니다. 대체 리뷰는 독립 검증이 아니므로 보고에도 "교차 리뷰 대체(같은 회사 모델 <모델 이름>)"이나 "교차 리뷰 대체(새 컨텍스트 없음, 메인 세션 자기 리뷰)"로 적어 사용자가 보고 판단하게 합니다. run-flow가 불렀으면 상태 파일의 `- 교차 리뷰 모델:`에도 적습니다.
  - 다른 회사 모델이 했으면 `- 교차 리뷰: 완료 (<수행한 모델>)`
  - 같은 회사 모델의 새 컨텍스트로 대체했으면 `- 교차 리뷰: 대체 (같은 회사 모델 <수행한 모델>)`
  - 자기 리뷰로 대체했으면 `- 교차 리뷰: 대체 (새 컨텍스트 없음, 메인 세션 자기 리뷰)`

### 여러 티켓 실행

번호 범위나 "남은 티켓 전부"를 요청하면 실행 방법이 갈립니다. 기본은 이 세션이 티켓을 하나씩 직접 구현하는 차례 실행입니다. 병렬 실행은 사용자의 선택(워커 도구 절차를 지정했거나 레포·에이전트 규칙에 등록해 둔 것)이 있을 때만 씁니다. 함께 시작할 수 있는 티켓이 둘 이상이고, 통합 브랜치를 공유하는 티켓이 없고, 쓸 수 있는 워커 도구 절차가 있으면 병렬 실행을, 하나라도 아니면 차례 실행을 합니다.

**병렬 실행**: 사용자가 고른 때만 쓰는 선택 경로입니다. 티켓마다 워커를 띄워 현재 브랜치에서 갈라진 worktree에서 구현시킵니다. 이 세션은 조정자로서 막힘 관계 순서를 지키고, 끝난 브랜치를 머지하고, 완료 기록을 남기고, 교차 리뷰를 부릅니다.

1. 작업 트리가 깨끗해야 합니다. 커밋하지 않은 brief·티켓 문서는 워커가 읽지 못하므로 커밋할지 묻습니다. 이어 받는 실행이면 끊긴 머지 복구(3번)를 이 검사보다 먼저 합니다.
2. 실행 묶음, 워커를 띄울 도구, 머지할 브랜치, 동시 워커 수(기본 3개), 시작 HEAD를 보여 주고 승인을 받습니다. 현재 브랜치가 기본 브랜치면 작업 브랜치를 만들지 함께 묻습니다.
3. 앞선 실행의 워커가 남아 있으면 새로 만들지 않고 이어 받습니다. 끝났지만 머지하지 않은 티켓이 있으면 다시 띄우지 않고 머지부터 합니다. 실행 중인 워커는 새로 띄우지 않고 상태를 확인하며 기다립니다. 막는 티켓이 끝났는데 완료 기록에 `- 교차 리뷰: 완료 (...)`나 `- 교차 리뷰: 대체 (...)` 줄이 없으면, 막힌 티켓을 띄우기 전에 교차 리뷰부터 합니다. 앞선 실행이 남긴 `- 교차 리뷰: 건너뜀 (...)` 줄은 리뷰하지 않은 것으로 봅니다. 막힌 티켓을 아직 띄우지 않았으면 교차 리뷰를 다시 하고, 이미 띄웠거나 머지했으면 통합 리뷰가 그 범위를 함께 본다고 완료 기록에 적습니다. 워커 식별자는 생기자마자 보고하고, 부른 쪽이 기록 파일을 넘겼으면 거기에 적습니다.
4. 막는 티켓이 모두 머지되고 그 교차 리뷰까지 끝난 티켓부터 워커를 띄웁니다. 워커는 티켓을 구현해 티켓 브랜치에 커밋하고 결과를 보고합니다. 워커 질문에 준 답과 앞서 내린 결정은 뒤에 띄우는 워커의 지시에 넣습니다.
5. 끝난 브랜치를 현재 브랜치로 합친 뒤 머지 커밋을 만들기 전에 레포 검증 명령(타입 검사, 린트, 테스트)을 돌립니다. run-flow가 보호 경로 검사를 넘겼으면 합친 결과와 워커의 티켓 브랜치에서 보호 목록의 파일이 바뀌지 않았는지도 봅니다. 바뀌었으면 머지를 되돌리고 멈춥니다. 통과하면 완료 기록을 머지 커밋에 넣고 워커와 worktree를 정리합니다. GitHub 티켓은 머지 커밋을 만든 뒤에 닫습니다. 실패하면 머지를 되돌리고 새 워커를 띄우지 않고 멈춥니다. 멈추기 전에 이 세션이 직접 원인을 찾아, 어느 쪽 변경에서 생긴 실패로 보이는지와 근거를 함께 보여 줍니다. 머지한 티켓이 다른 티켓을 막으면 막힌 티켓을 띄우기 전에 그 머지에 교차 리뷰만 먼저 합니다. 이 리뷰 없이 막힌 티켓을 띄우지 않고, 다른 회사 모델을 쓸 수 없으면 같은 회사 모델의 새 컨텍스트 리뷰로 대체합니다. 끝나면 완료 기록에 ``- 교차 리뷰: 완료 (`<머지 커밋 해시>`, <수행한 모델>)``이나 ``- 교차 리뷰: 대체 (`<머지 커밋 해시>`, 같은 회사 모델 <수행한 모델>)`` 줄을 남깁니다. 충돌하면 워커에게 리베이스를 맡기고, 다시 충돌하면 멈추고 알립니다. 실패한 티켓과 그 티켓에 막힌 티켓은 실행하지 않습니다.
6. 모두 끝나면 시작 HEAD부터 지금까지를 한 번 리뷰하고, 교차 리뷰 줄이 없는 티켓의 완료 기록에 그 결과를 더한 뒤, brief의 "확인 기준"을 실행하고 결과와 커밋 목록을 보고합니다. push, PR, 기본 브랜치 머지는 사용자가 정합니다.

워커를 만들고, 기다리고, 정리하는 방법은 고른 워커 도구 절차가 정합니다. 절차는 다음 항목을 그 도구의 방법으로 채웁니다. 항목의 조건은 `references/multi-ticket.md`의 "워커 도구 절차"에 있습니다.

| 항목 | 절차가 정하는 것 |
|---|---|
| 사용 조건 | 이 세션에서 그 도구로 워커를 띄울 수 있는지 확인하는 방법 |
| 워커 만들기 | 워커를 띄울 때 현재 브랜치의 로컬 ref에서 갈라진 새 worktree와 새 브랜치를 만드는 방법, 워커 spec을 넘기는 방법, 워커의 모델과 effort를 정하는 순서 |
| 기다리기 | 워커가 끝나거나, 묻거나, 멈추거나, 권한을 요청했을 때 알림을 받는 방법. 상태를 되풀이해 조회하지 않습니다. |
| 끝 판정 | 알림과 마지막 보고를 통과, 질문, 실패로 가르는 방법. 보고한 커밋이 티켓 브랜치에 있을 때만 통과입니다. |
| 같은 워커에 보내기 | 질문 답과 리베이스 요청을 새 워커가 아닌 그 워커에 보내는 방법 |
| 이어 받기 | 기록한 워커 식별자로 남은 워커를 찾아 상태와 마지막 보고를 읽는 방법 |
| 정리 | 머지한 뒤 워커를 닫고 worktree와 머지된 티켓 브랜치를 지우는 방법. 실패한 티켓의 것은 남깁니다. |
| 워커 식별자 | 기록할 값과 형식. 도구 이름과 워커를 찾는 데 필요한 ID를 담습니다. |
| 교차 리뷰 워커 | 다른 회사 모델의 워커를 지금 작업 트리에 읽기 전용으로 띄워 diff 범위, brief 전문, 기준 목록을 넘기는 방법, 그 모델과 effort를 고르는 순서, 지적과 수행한 모델 이름을 보고받는 방법. 모델은 절차에 고정하지 않고, 다른 회사 모델을 고를 수 없으면 워커를 띄우지 않습니다. |

**차례 실행**: 기본 방법입니다. 이 세션이 티켓을 하나씩 직접 구현하고, 티켓마다 서브에이전트를 띄우지 않습니다. 한 티켓의 완료 기록을 남긴 뒤 다음 티켓을 시작합니다. 같은 작업 트리를 고치므로 티켓 둘을 함께 진행하지 않고 커밋하지 않습니다. 완료 기준을 통과하지 못한 티켓이 나오면 같은 세션에서 최초 시도를 포함해 3회까지 하고, 그래도 실패하면 뒤 티켓을 시작하지 않고 멈춥니다. 모두 끝나면 전체 변경을 한 번 리뷰하고, 교차 리뷰 결과를 티켓마다 완료 기록에 더한 뒤 brief의 "확인 기준"을 실행합니다. 레포 규칙이나 사용자 결정으로 도중에 커밋했으면 그 커밋도 리뷰 대상에 넣습니다.

## 결과물

- 구현한 코드 변경. 커밋하지 않습니다. 병렬 실행에서는 티켓마다 머지 커밋이 생깁니다.
- 티켓에 붙는 완료 기록: 완료일, 커밋 정보(커밋 안 함과 작업 시작 HEAD, 병렬 실행이면 머지한 티켓 브랜치와 커밋), 바꾼 파일, 확인한 명령과 결과, 확인 못 한 기준, 교차 리뷰를 수행한 모델(대체했으면 대체했다는 표시), 교차 리뷰 지적의 판정, 고치지 않은 지적. 다른 티켓이 쓸 결과는 `## 산출물`에 남깁니다.
- 보고: 끝낸 티켓, 완료 기준 결과, 바꾼 파일, 산출물 위치, 교차 리뷰를 수행한 모델과 대체 표시, 교차 리뷰 지적의 판정, 고치지 않은 리뷰 지적, 건너뛴 리뷰(규칙 검사를 하지 못했거나 리뷰 스킬을 쓰지 않은 경우), 다음 티켓

## 함께 쓰는 스킬

- **set-brief**, **set-ticket**: 실행할 brief와 티켓을 만듭니다.
- **run-flow**: 5단계에서 이 스킬로 brief의 남은 티켓을 실행합니다.
- **code-review** 스킬이 설치돼 있으면 5단계 코드 리뷰에 씁니다.
- **check-guidelines**: 5단계 규칙 검사에 씁니다.
