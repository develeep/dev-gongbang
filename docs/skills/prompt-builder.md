# prompt-builder

만들 프롬프트를 인터뷰로 정리해, 대상 모델에 맞춘 완성 프롬프트를 채팅에서 받을 수 있습니다. 프롬프트 내용은 인터뷰에서 받은 값과 승인한 제안으로만 채웁니다. 구조와 문구는 Claude·OpenAI 공식 best practice를 따르고, 대상 모델의 전용 가이드가 있으면 그 가이드로 조정합니다. 초안이 있으면 초안에서 비어 있거나 모호한 항목만 묻습니다.

| 항목 | 값 |
|---|---|
| 버킷 | productivity |
| 호출 방식 | User-invoked |
| 호출 | `/gongbang:prompt-builder [초안 경로 또는 만들 프롬프트 설명]` |
| 원문 | [SKILL.md](../../skills/productivity/prompt-builder/SKILL.md) |

**목차**: [언제 쓰나](#언제-쓰나) · [준비물](#준비물) · [진행 과정](#진행-과정) · [결과물](#결과물) · [커스텀](#커스텀) · [함께 쓰는 스킬](#함께-쓰는-스킬)

## 언제 쓰나

- 챗봇이나 서비스에 넣을 API 시스템 프롬프트를 만들 때
- 도구를 쓰는 에이전트나 오래 자율 실행할 하네스 프롬프트를 만들 때
- 분석, 문서 작성 같은 한 번 쓸 작업 프롬프트를 만들 때
- CLAUDE.md나 SKILL.md 본문을 쓸 때
- 이미 있는 프롬프트 초안을 고치거나 리뷰할 때

## 준비물

- 초안이 있으면 본문, 파일 경로, 첨부 중 하나로 넘기세요.
- 대상 모델을 정해 두세요. 아래 모델은 전용 가이드가 있습니다. 가이드는 스킬 폴더의 `reference/models/`에 있습니다.

  | 대상 모델 | 가이드 파일 |
  |---|---|
  | Claude Opus 5.5 | `opus-5-5.md` |
  | Claude Opus 5 | `opus-5.md` |
  | Claude Sonnet 5.5 | `sonnet-5-5.md` |
  | Claude Sonnet 5 | `sonnet-5.md` |
  | Claude Fable 5.2, Mythos 5.2 | `fable-5-2.md` |
  | Claude Fable 5.1, Mythos 5.1 | `fable-5-1.md` |
  | Claude Haiku 5.5 | `haiku-5-5.md` |
  | Claude Haiku 4.5 | `haiku-4-5.md` |
  | GPT-6.2 Astra, GPT-6.2 Sol | `gpt-6-2.md` |
  | GPT-6 Astra | `gpt-6-astra.md` |
  | GPT-6.1 Sol | `gpt-6-1-sol.md`. GPT-6 Astra 가이드도 함께 읽습니다 |

  표에 없는 모델은 모델 전용 조정 없이 공통 best practice만 적용합니다. 표에 없는 GPT 모델이면 Claude 전용 항목(prefill, 사고 설정)도 적용하지 않고, 실행 설정 권고에는 모델 ID만 적습니다.

## 진행 과정

1. **세션 모델 감지**: 이 세션의 모델 ID를 확인해 첫 응답에 한 줄로 알립니다. Claude든 GPT든 감지한 모델이 대상 모델 질문의 첫 선택지가 됩니다. 감지하지 못하면 `세션 모델: 확인 불가`라고 알리고, 세션 모델 선택지 없이 대상 모델을 묻습니다.
2. **기본 설정**: 아래 네 가지를 한 라운드에 묻습니다. 요청이나 초안에서 분명한 항목은 묻지 않고 되짚기만 합니다.
   - **종류**: API 시스템 프롬프트 / 에이전트·하네스 프롬프트 / 단발 작업 프롬프트 / CLAUDE.md·SKILL.md 본문. CLAUDE.md·SKILL.md 본문은 대상 모델 대신 사용 모델을 묻고, 여러 개를 고를 수 있습니다.
   - **대상 모델**: 이 프롬프트를 실제로 돌릴 모델
   - **프롬프트 언어**: 한국어 / 영어. 다른 언어는 직접 입력합니다.
   - **진행 방식**: 빠른 모드는 필수 항목만 묻고 나머지는 기본값 표로 한 번에 승인받습니다. 상세 인터뷰는 모든 항목을 라운드별로 묻습니다.

   세션 모델과 대상 모델이 다르면, 이 세션에서 바로 시험한 결과가 대상 모델의 동작과 다를 수 있다고 알립니다.
3. **모델 가이드 읽기와 확인일 점검**: 대상 모델의 가이드를 읽고, 어떤 가이드를 적용하는지 한 줄로 알립니다. 가이드 맨 위의 확인일이 90일 이상 지났고 웹 페이지를 가져와 읽을 수 있으면, 출처 문서와 기본 effort, 사고 설정(GPT는 지원하는 reasoning effort 값), 베타 헤더, 400 오류 조건을 대조합니다. 다르면 출처를 따르고 차이를 알립니다.
4. **초안 분석** (초안이 있을 때): 초안에서 추출한 값을 `항목 | 초안에서 추출한 값 | 상태` 표로 보여 주고 맞는지 확인받습니다. 이후 인터뷰에서는 상태가 모호하거나 없는 항목만 묻습니다. 모델 가이드의 "제거 검토" 목록에 해당하는 문구가 초안에 있으면 목록으로 보여 주고 하나씩 지울지 묻습니다.
5. **구성 요소 인터뷰**: 종류별 라운드 순서대로 묻습니다. 선택형 항목은 선택지를 보여 주는 질문 도구로, 도구가 없으면 번호 목록으로 묻습니다. 배경, 규칙, 예시 같은 서술형 항목은 번호 질문으로 한 메시지에 모아 묻습니다. 라운드마다 받은 답을 짧게 되짚고 다음 라운드로 넘어갑니다.
6. **보완 제안과 모델별 결정 질문**: 받은 값만으로는 실행하는 모델이 기준 없이 판단해야 하는 곳(무엇을 보고하고 뺄지, 분류 경계와 확신도 기준, 모를 때의 행동)이 있으면 초안을 제안하고 승인·수정·제외를 받습니다. 메뉴 경로, 정책, 가격, 연락처 같은 조직이나 제품 고유의 사실은 제안하지 않고 묻습니다. 이어서 모델 가이드의 결정 질문 중 지금까지의 답에 해당하는 것만 묻습니다.
7. **조립과 자체 검수**: 조립 골격(GPT는 모델 가이드의 조립 골격)에 받은 값을 배치하고, 공통 검수 목록과 모델 가이드의 검수 항목으로 점검합니다. 정보가 없어 통과하지 못한 항목은 질문으로 해결합니다. "생략"을 골라 끝내 통과하지 못한 항목은 결과의 "다음 단계"에 경고로 남깁니다.
8. **출력**: 아래 결과물 구조로 전달합니다.

## 결과물

채팅에 네 부분으로 나옵니다. 완성 프롬프트를 바로 복사할 수 있도록 네 부분 사이에 다른 설명 문단을 넣지 않습니다.

1. **설계 요약**: 대상 모델과 적용한 가이드(가이드 확인일, 이번 세션에서 대조했는지), 종류·언어·진행 방식, 반영한 결정, 제안해 넣은 내용, 적용한 best practice
2. **완성 프롬프트**: 그대로 복사해 `.md` 파일로 저장할 수 있는 코드블록. system과 user 템플릿처럼 메시지가 여럿이면 메시지마다 블록을 나눕니다.
3. **실행 설정 권고**: API·에이전트 종류일 때만 나옵니다. Claude는 effort, `max_tokens`, 사고 설정 등, GPT는 reasoning effort, verbosity, `max_output_tokens` 등을 권고합니다.
4. **다음 단계**: 테스트 방법, 생략하거나 기본값으로 둔 항목 중 품질에 영향을 줄 수 있는 것, 조립하면서 스스로 정한 형식 선택, 승인받지 못한 제안(넣을 문장과 위치)

모델 불일치, 품질에 영향을 줄 수 있는 생략·기본값 항목, 승인받지 못한 제안, 통과하지 못한 검수 항목 같은 경고는 응답을 짧게 줄일 때도 빼지 않습니다.

파일은 기본적으로 저장하지 않습니다. SKILL.md에 번들 파일이 있으면 파일마다 블록을 나눠 보여 주고, 저장할지와 위치(사용자 스킬 폴더 / 프로젝트 스킬 폴더 / 저장 안 함)를 묻습니다. 저장을 요청하면 경로를 확인받은 뒤 저장합니다. 같은 이름의 파일이 있으면 덮어쓰기 전에 확인받습니다.

## 커스텀

| 바꾸고 싶은 것 | 고칠 파일 |
|---|---|
| 모델 가이드 내용 | `reference/models/<모델>.md` |
| 새 모델 지원 | `reference/models/`에 가이드를 추가하고, SKILL.md 3단계의 "모델 ID 패턴" 표에 줄을 추가. 대상 모델 선택지에 넣으려면 `reference/interview.md`의 B1 줄도 고침 |
| 인터뷰 항목, 빠른 모드 기본값 | `reference/interview.md` |
| 모든 모델에 공통인 원칙, 조립 골격, 검수 목록 (Claude 전용 항목은 "(Claude 대상)"으로 표시) | `reference/principles.md` |
| 최종 응답 구조, 파일 저장 조건 | `reference/output-format.md` |
| CLAUDE.md·SKILL.md 작성 규칙 | `reference/skill-authoring.md` |

스킬을 복사해서 고치는 방법은 [커스텀 가이드](../customization.md)를 보세요.

## 함께 쓰는 스킬

- **framing-problems**: 한 번 쓸 프롬프트는 framing-problems로 작업을 먼저 구체화하고, 확정된 기록을 초안으로 넘기세요. 사람과 대화하며 진행하는 에이전트 프롬프트나 재사용 템플릿은 인터뷰에서 "실행 시 구체화"를 고르면, 완성 프롬프트가 실행될 때마다 작업 전에 framing-problems를 호출합니다. 실행 환경에 그 스킬이 설치돼 있어야 합니다.
- **building-skills**: SKILL.md 초안을 만든 뒤 그 출력을 building-skills에 넘기면 테스트와 수정을 이어 갑니다.
