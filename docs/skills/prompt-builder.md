# prompt-builder

인터뷰로 받은 값과 승인한 제안만으로 프롬프트를 조립한다. 구조와 문구는 Claude 공식 best practice를 따르고, 대상 모델 전용 가이드로 조정한다. 초안이 있으면 빈 항목만 묻고, 없으면 처음부터 인터뷰한다.

| 버킷 | productivity |
| 호출 방식 | User-invoked |
| 호출 | `/gongbang:prompt-builder [초안 경로 또는 만들 프롬프트 설명]` |
| 원문 | [SKILL.md](../../skills/productivity/prompt-builder/SKILL.md) |

## 언제 쓰나

- 챗봇이나 서비스에 넣을 API 시스템 프롬프트를 만든다.
- 도구를 쓰는 에이전트나 오래 자율 실행할 하네스 프롬프트를 만든다.
- 분석, 문서 작성 같은 한 번 쓸 작업 프롬프트를 만든다.
- CLAUDE.md나 SKILL.md 본문을 쓴다.
- 이미 있는 프롬프트 초안을 고치거나 리뷰한다.

## 준비물

- 초안이 있으면 본문, 파일 경로, 첨부 중 하나로 넘긴다.
- 대상 모델 가이드는 Opus 5.5, Opus 5, Sonnet 5.5, Sonnet 5, Fable 5.1, Haiku 4.5용이 있다. 다른 모델이면 모델 전용 조정 없이 공통 best practice만 적용한다.

## 진행 과정

1. 세션 모델을 감지해 알린다.
2. 기본 설정을 한 번에 묻는다. 프롬프트 종류, 대상 모델, 프롬프트 언어(한국어 / 영어), 진행 방식이다.
   - **빠른 모드**: 필수 항목만 묻고, 나머지는 기본값 표로 한 번에 승인받는다.
   - **상세 인터뷰**: 모든 항목을 라운드별로 묻는다.
3. 대상 모델 가이드를 읽는다. 가이드의 확인일이 90일 넘게 지났고 WebFetch를 쓸 수 있으면 공식 문서와 대조한다.
4. 초안이 있으면 항목별로 추출한 표를 보여 주고, 모호하거나 없는 항목만 이후에 묻는다.
5. 구성 요소를 인터뷰한다. 선택형은 선택창으로, 배경·규칙·예시 같은 서술형은 번호 질문으로 묻는다.
6. 받은 값만으로는 실행하는 모델이 기준 없이 판단해야 하는 곳이 있으면 초안을 제안하고 승인·수정·제외를 받는다. 이어서 모델별 결정 질문을 묻는다.
7. 프롬프트를 조립하고 자체 검수한 뒤 결과를 낸다.

## 결과물

채팅에 네 부분으로 나온다.

1. **설계 요약**: 대상 모델, 적용한 가이드, 반영한 결정, 제안해 넣은 내용
2. **완성 프롬프트**: 그대로 복사해 `.md` 파일로 저장할 수 있는 코드블록
3. **실행 설정 권고**: API·에이전트 종류일 때만. effort, `max_tokens`, 사고 설정 등
4. **다음 단계**: 테스트 방법, 생략한 항목의 영향, 승인받지 못한 제안

파일은 기본적으로 저장하지 않는다. SKILL.md에 번들 파일이 있거나 사용자가 저장을 요청하면 경로를 확인받은 뒤 저장한다.

## 함께 쓰는 스킬

- **framing-problems**: 한 번 쓸 프롬프트는 framing-problems로 작업을 먼저 구체화하고, 확정된 기록을 초안으로 넘긴다. 에이전트 프롬프트나 재사용 템플릿은 인터뷰에서 "실행 시 구체화"를 고르면, 완성 프롬프트가 실행될 때마다 framing-problems를 호출한다. 실행 환경에 그 스킬이 설치돼 있어야 한다.
- **building-skills**: SKILL.md 초안을 만든 뒤 그 출력을 building-skills에 넘기면 테스트와 수정을 이어 간다.
