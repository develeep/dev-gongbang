# set-guidelines

레포의 언어와 프레임워크에 맞는 코딩 가이드를 [awesome-guidelines](https://github.com/Kristories/awesome-guidelines) 목록에서 골라, 그 원문에서 뽑은 규칙으로 레포의 규칙 파일과 설정을 만들 수 있습니다. 만들 수 있는 것은 `.claude/rules/` 규칙 파일, CLAUDE.md/AGENTS.md, 린터·포매터 설정이고, 무엇을 어디에 만들지는 사용자가 고릅니다. 파일은 최종 승인을 받은 뒤에만 씁니다.

## 언제 쓰나

- 레포에 코딩 규칙이나 린터·포매터 설정이 없어 새로 만들 때
- 이미 있는 규칙을 고치거나 보탤 때
- 기존 규칙을 걷어 내고 새로 정할 때

## 준비물

- 가이드 원문을 웹에서 읽을 수 있어야 합니다. 링크가 깨졌거나 원문을 읽을 수 없는 가이드는 건너뜁니다.
- 린터·포매터 설정을 만들면 그 도구를 실행해 설정을 확인합니다. 도구가 설치돼 있지 않으면 설치해서 확인할지 묻습니다.

## 진행 과정

1. **레포 파악과 확인**: 레포를 살펴 언어와 프레임워크를 정하고, 맞는지 확인받습니다. 레포에 이미 있는 컨벤션 문서, CLAUDE.md/AGENTS.md, `.claude/rules/`, 린터·포매터 설정도 함께 찾습니다.
2. **기존 규칙 처리 방식 결정**: 1단계에서 기존 규칙을 찾았을 때만 고릅니다.
   - **개선·추가**: 기존 규칙을 유지하고, 고칠 점과 더할 규칙을 추천합니다.
   - **초기화**: 기존 규칙을 걷어 내고 새로 정합니다.
3. **가이드·도구 추천과 선택**: `reference/guides-index.md`에서 1단계에서 확인한 언어, 프레임워크, 플랫폼, 도구의 절을 찾아 가이드와 린터·포매터를 추천하고, 사용자가 고르게 합니다. 목록에 그 언어의 린터·포매터가 없으면 그 언어에서 널리 쓰는 도구를 추천하고 "awesome-guidelines 목록 밖"이라고 표시합니다.
4. **원문 읽기와 규칙 추출**: 고른 가이드의 원문을 읽어 이 레포에 적용할 규칙을 뽑습니다.
   - 고른 가이드끼리 규칙이 충돌하면 나란히 보여 주고 하나를 고르게 합니다. 어느 쪽이 맞는지는 팀의 선호라서 가이드만 보고 정할 수 없기 때문입니다.
   - 아키텍처 규칙은 고른 가이드가 아키텍처를 다룰 때만 뽑습니다. API 설계 규칙은 분야 규칙으로 다룹니다.
5. **산출물 선택과 최종 승인**: 만들 산출물과 레포에 맞는 경로를 고릅니다. 만들거나 바꾸거나 지울 파일 목록과 내용 요약, 규칙 파일마다 적용할 `paths` 패턴을 보고 최종 승인합니다.
6. **작성**: 승인한 파일만 씁니다. 린터·포매터 설정을 만들었으면 그 도구를 실행해 설정이 오류 없이 읽히는지 확인하고, 오류가 나면 고친 뒤 다시 실행합니다.

가이드에서 뽑은 규칙이 팀 규칙과 다르면 팀 규칙을 따릅니다. 가이드는 일반론이고, 팀 규칙은 이 레포에서 이미 합의한 결정이기 때문입니다. 팀 규칙은 레포에 이미 있는 규칙(컨벤션 문서, CLAUDE.md/AGENTS.md, `.claude/rules/`, 린터·포매터 설정)과, 산출물을 만든 뒤 CLAUDE.md/AGENTS.md의 "팀 규칙" 절에 추가하는 규칙입니다. 2단계에서 초기화를 고르면 기존 규칙은 가이드 규칙보다 앞서지 않습니다.

## 결과물

고른 산출물만 만듭니다.

| 산출물 | 양식 | 내용 |
|---|---|---|
| 분야별 규칙 파일 `.claude/rules/<분야>.md` | `templates/rule.md` | `paths`에 파일 패턴을 적으면 그 파일을 다룰 때만 로드되고, `paths`가 없으면 CLAUDE.md처럼 세션마다 로드됩니다. 특정 파일에만 해당하는 분야는 `paths`에 그 파일 패턴을 적습니다 |
| CLAUDE.md / AGENTS.md | `templates/agent-instructions.md` | "팀 규칙" 절과 "규칙" 절로 나뉩니다. 세션마다 컨텍스트에 올라가므로 핵심 규칙만 두고 세부는 규칙 파일로 옮기며, 린터·포매터가 강제하는 규칙은 다시 적지 않습니다 |
| 린터·포매터 설정 | 고른 도구의 문서 | 도구를 실행해 오류 없이 읽히는지 확인합니다 |

CLAUDE.md와 AGENTS.md를 둘 다 만들면 CLAUDE.md에 `@AGENTS.md` 줄을 넣습니다. 둘이 함께 있으면 Claude Code가 CLAUDE.md만 읽기 때문입니다.

산출물 파일에는 출처 표시, 링크, 템플릿에 없는 절(가이드와 다르게 한 이유, 적용하지 않은 규칙 등)을 넣지 않습니다.

## 커스텀

| 바꾸고 싶은 것 | 고칠 파일 |
|---|---|
| 추천할 가이드와 도구 목록 | `reference/guides-index.md` (awesome-guidelines README 스냅샷, 2026-10-28) |
| 규칙 파일 양식 | `templates/rule.md` |
| CLAUDE.md / AGENTS.md 양식 | `templates/agent-instructions.md` |

사내 가이드를 추천 후보에 넣으려면 `reference/guides-index.md`에서 그 언어나 도구의 절에 링크를 추가하세요. 스킬을 복사해서 고치는 방법은 [커스텀 가이드](../customization.md)를 보세요.

## 함께 쓰는 스킬
