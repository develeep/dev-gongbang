# analyzing-requirements

기획서를 읽고 요구사항, 서비스·개발 영역별 개발 범위, 기획서 섹션별 내용을 마크다운 문서로 정리한다. 이 문서는 개발자나 에이전트가 기획서 대신 읽는다. 그래서 기획서에 없는 내용은 채우지 않고, 모호한 부분은 먼저 묻는다.

> 만드는 중인 스킬이다. `gongbang-dev`를 설치해야 쓸 수 있고, 동작이 바뀔 수 있다.

## 언제 쓰나

- 기획서 링크나 파일을 받아 요구사항을 정리하거나 분석한다.
- 개발을 시작하기 전에 서비스와 개발 영역(web, api 등)별로 무엇을 만들지 나눈다.

"이 기획서 요구사항 정리해 줘"처럼 기획서를 주며 요청하면 이름을 입력하지 않아도 Claude가 이 스킬을 고를 수 있다.

## 준비물

- 기획서: PDF, PPT(X), MD 파일, 또는 SharePoint·OneDrive 같은 링크
- 링크로 줄 때는 그 링크를 읽을 커넥터나 MCP 도구가 연결돼 있어야 한다. 읽지 못하면 정리를 시작하지 않는다.

## 진행 과정

1. 기획서를 끝까지 읽고 섹션 구성, 서비스, 개발 영역을 파악한다.
2. 모호한 부분을 번호 목록으로 한 번에 묻는다. 질문마다 무엇이 왜 모호한지 적는다.
3. 템플릿에 따라 문서를 쓴다.
4. 항목마다 기획서나 답변에 근거가 있는지 확인한다. 근거가 없으면 지우거나 `확인 필요`로 바꾼다.
5. 저장할 경로를 묻고 마크다운 파일로 저장한다.

## 결과물

마크다운 문서 하나.

- **개발 범위**: `서비스 | 개발 영역 | 내용` 표. 항상 넣는다.
- **요구사항**: 항상 넣는다.
- **기획서에 있는 섹션**: as-is, to-be, 화면 목록, 기능 목록, 일정 등. 기획서에 있는 것만 기획서 순서대로 넣는다.
- **확인 필요**: 답을 받지 못한 항목. 본문의 해당 자리에도 `확인 필요`로 표시한다.
