# 개발 규칙

메인 세션이 따르는 규칙입니다. 메인 세션 하나가 기획서부터 PR까지의 일을 직접 합니다. task 서브에이전트는 이 파일을 받지 않습니다.

## 개발 단계

기획서부터 PR까지 아래 순서로 진행합니다. 사용자가 `/skill:run-flow`를 실행하면 run-flow 스킬이 이 순서를 이어서 진행합니다. 단계를 하나씩 진행할 때는 단계가 끝나면 결과물 위치와 다음 단계를 알립니다.

| 순서 | 단계 | 스킬 | 결과물 | 사용자 확인 |
|---|---|---|---|---|
| 1 | 요구사항 정리 | analyzing-requirements | 요구사항·개발 범위 문서 | 저장 위치 |
| 2 | 문제 구체화 | framing-problems | 구체화 기록 | 기록 확정 |
| 3 | 작업 지시서 | set-brief | brief | 초안과 게시 위치 |
| 4 | 티켓 분할 | set-ticket | 티켓 | 크기와 순서 승인 |
| 5 | 티켓 구현 | run-ticket | 코드, 완료 기록 | 실행 순서 |
| 6 | 규칙 검사·교차 리뷰 | run-ticket의 리뷰 단계 | 리뷰 보고 | 머지 여부 결정 |
| 7 | PR | 메인 세션이 본문 작성, run-flow가 PR 생성 | PR | PR 본문 |

여러 티켓은 메인 세션이 하나씩 차례로 직접 실행합니다. 병렬 실행은 선택입니다. 사용자나 규칙이 쓸 수 있는 워커 도구 절차를 지정했고 run-ticket의 병렬 실행 조건을 만족할 때만 run-ticket이 그 절차로 병렬 실행합니다. 병렬 경로에서 통합 검증이 실패하면 메인 세션이 직접 원인을 찾습니다.

## 위임

완성도가 먼저이므로 맥락을 잃는 분리는 하지 않습니다. 메인 세션이 brief 초안, 구현, 완료 기준과 화면 확인, 실패한 티켓의 원인 정리, 코드 리뷰와 규칙 검사, PR 본문을 직접 하고, 자기 산출물을 검증하고 그 결과를 반영해 완성하는 것까지 책임집니다. 새 컨텍스트가 있어야 하는 검증 두 가지만 읽기 전용 호출로 띄우고, 그 결과는 메인 세션이 받아 검증하고 반영합니다.

| 작업 | 에이전트 |
|---|---|
| 교차 리뷰 (버그, 작업 경계와 레포 규칙 위반, 인증·권한·결제·개인정보를 다루는 변경이면 보안) | code-reviewer |
| brief 냉독 읽기 (메인 세션이 독자 3명을 한 메시지에서 함께 띄움) | cold-reader |

교차 리뷰는 이번 변경을 구현한 모델과 다른 회사의 모델이 맡습니다. code-reviewer는 사용자가 `modelRoles.review`에 적은 모델로 돕니다. 그 값이 비어 있으면 omp는 code-reviewer를 메인 세션 모델로 돌리므로, 이때의 리뷰는 같은 회사 대체로 기록합니다. 모델을 고르는 순서와, 다른 회사 모델을 쓸 수 없을 때 같은 회사 모델로 대체하고 완료 기록에 적는 방법은 run-ticket이 정합니다. 교차 리뷰를 건너뛰지 않습니다.

code-reviewer는 읽기 전용이고 하위 에이전트를 띄우지 않습니다. 메인 세션은 호출 전후의 코드 지문을 비교하고, 바뀌었으면 그 리뷰 결과를 쓰지 않고 바뀐 것을 사용자에게 보여 준 뒤 다음 수단으로 다시 맡깁니다. 지적은 하나씩 재현하거나 코드·규칙 원문과 대조해 `수용 / 기각(사유) / 범위 밖`으로 적습니다.

레포 규칙이 정한 리뷰 스킬은 메인 세션이 하위 에이전트를 띄우지 않는 방식으로 직접 실행합니다. 그렇게 실행할 수 없으면 직접 리뷰하고 보고에 적습니다.

## 넘기는 것

- code-reviewer에는 리뷰할 diff 범위(작업 시작 HEAD 기준), brief 전문, 볼 기준 목록, 레포 규칙 파일 경로를 넘깁니다. 비밀값과 원문 로그는 넘기지 않습니다.
- diff가 리뷰 모델의 입력 한도를 넘으면 디렉터리별로 나눠 맡깁니다. 나눌 때는 디렉터리를 넘는 공유 타입, API, 설정을 리뷰마다 함께 넘기고, 디렉터리 경계를 넘는 결함은 메인 세션이 봅니다.
- cold-reader에는 대화 없이 brief 초안 전문, 저장소 경로, 정해진 질문만 넘깁니다.
- 커밋 메시지는 메인 세션이 레포 커밋 규칙대로 씁니다.

## 실패했을 때

실패는 완료 기준이나 테스트를 통과하지 못한 것입니다.

1. 메인 세션이 같은 루프에서 원인을 정리하고 다시 합니다. 실패 원인이 티켓의 모호함이나 크기면 다시 하지 않고 2번처럼 멈춥니다.
2. 최초 시도를 포함해 3회 안에 통과시키지 못하면 멈춥니다. 상태 파일의 `- 멈춘 이유:`에 시도 횟수와 원인을 적고, `/skill:set-ticket`으로 티켓을 다시 나누자고 제안합니다. 이어 받은 흐름에 앞선 실패 기록이 있으면 그 횟수부터 셉니다.
3. 더 강한 모델이 필요하면 사용자가 세션 모델을 바꿔 상태 파일로 이어 갑니다.
