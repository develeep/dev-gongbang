# 최종 응답 구조

아래 순서로 응답한다.

## 1. 설계 요약 (짧게)

```
## 프롬프트 설계 요약
- 대상 모델: <모델 ID> (세션 모델 / 사용자 지정) · 적용 가이드: 공통 + <모델 가이드 또는 "공통만"> (확인일 <날짜>, 이번 세션 대조 <함/안 함>)
- 종류: <API 시스템 / 에이전트 / 단발 / CLAUDE.md·SKILL.md> · 언어: <B2> · 진행 방식: <빠른 모드 / 상세 인터뷰>
- 반영한 결정: <사용자 결정 3~6개를 한 줄씩>
- 적용한 best practice: <핵심 3~6개를 한 줄씩>
```

## 2. 완성 프롬프트

- 프롬프트 전체를 하나의 코드블록에 넣어 그대로 복사해 `.md` 파일로 저장할 수 있게 한다.
- 펜스는 `markdown` 언어 태그를 쓰고, 프롬프트 안에 있는 어떤 펜스보다 길게 만든다. 안에 ``` 가 있으면 ```` 를 쓴다.
- system과 user 템플릿처럼 메시지가 여러 개면 메시지마다 블록을 나누고, 블록 위에 `### system` / `### user (템플릿)` 제목을 단다.
- 블록 안에는 프롬프트 본문만 넣는다. 해설 주석은 넣지 않는다.

### 파일 저장 (조건부)

기본은 채팅 출력만 하고 파일을 저장하지 않는다. 다음 경우에만 저장한다.

- **SKILL.md에 번들 파일이 있을 때**(K6=필요): 파일마다 블록을 나누고 블록 위에 `### <스킬 폴더 기준 상대 경로>` 제목을 단다. 그다음 저장할지와 위치를 묻는다. 위치 선택지는 사용자 스킬(`~/.claude/skills/<이름>/`) / 프로젝트 스킬(`.claude/skills/<이름>/`) / 저장 안 함이다.
- **사용자가 저장을 요청했을 때**: 경로를 확인받는다.

저장할 경로에 같은 이름의 파일이 있으면 덮어쓰기 전에 그 사실을 알리고 확인받는다. 저장한 뒤에는 저장한 파일 목록을 보여 준다.

## 3. 실행 설정 권고 (API·에이전트 종류일 때만)

모델 가이드의 "실행 설정 권고"에서 사용자 답에 맞는 항목만 고른다. 대상 모델이 effort를 지원하지 않으면(예: Haiku 4.5) `output_config.effort` 줄을 빼고 `thinking` 줄에 모델 가이드의 설정을 쓴다.

```yaml
model: <모델 ID>
output_config:
  effort: <값>   # 한 줄 근거
max_tokens: <값>  # 근거
thinking: <설정>
betas: [<필요할 때만>]
```

그 아래에 하네스 쪽 권고(턴 범위 시스템 메시지, 자동 계속 로직 등)가 있으면 3줄 이내로 적는다.

## 4. 다음 단계

- 대표 입력 3개 이상으로 테스트하고, effort 수준을 바꿔 가며 비교하라고 안내한다. 공식 가이드가 모든 모델에서 자체 평가를 권장한다.
- 세션 모델과 대상 모델이 다르면, 테스트는 대상 모델로 해야 한다고 알린다.
- 인터뷰에서 "생략"했거나 빠른 모드 기본값으로 처리한 항목 중 품질에 영향을 줄 수 있는 것을 한 줄씩 알린다.
- 조립하면서 스스로 정한 형식 선택(표 열 구성, 정렬 순서, 등급 척도 등)도 한 줄씩 밝힌다. 사용자가 고른 것이 아니므로 바꿀 수 있다고 알린다.
- 수정이 필요하면 해당 항목만 다시 물어 갱신하겠다고 안내한다.
