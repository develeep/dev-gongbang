# 6단계: 머지·PR 결정

먼저 리뷰가 지금 코드에 유효한지 확인한다. `## 리뷰`의 통합 리뷰 줄에 코드 지문이 있으면 지금 값과 비교한다. 다르면 리뷰한 뒤에 코드가 바뀐 것이므로 그렇다고 알리고, 아래 "고치기"의 재리뷰부터 한다. 지문 없이 `완료`만 적힌 기록은 지금 코드와 같은지 확인할 수 없다고 함께 보여 준다.

run-ticket의 보고에서 티켓별 완료 기준 결과, 고치지 않은 리뷰 지적, 건너뛴 리뷰, 바뀐 파일과 커밋을 한 메시지로 모아 보여 주고 셋 중 하나를 고르게 한다.

6단계부터 시작해 run-ticket의 보고가 없으면 아래에서 모은다.

- 상태 파일의 `## 리뷰`·`## 구현 중 결정`
- 티켓의 `## 완료 기록`(GitHub 티켓은 완료 코멘트)
- 상태 파일의 시작 HEAD(없으면 완료 기록의 작업 시작 HEAD)를 기준으로 한 `git log <시작 HEAD>..HEAD`, `git diff --stat <시작 HEAD>`, `git status --porcelain`의 새 파일. `git diff --stat <시작 HEAD>`는 커밋하지 않은 변경까지 보여 준다

`## 리뷰`가 `- 통합 리뷰: 기록 없음`이면 통합 리뷰 기록이 없다고 함께 보여 준다.

- **PR 만들기**: 다음을 함께 정한다. 커밋하지 않은 변경이 있으면 레포 커밋 규칙대로 커밋 하나로 묶고 그 메시지를 보여 준다. 현재 브랜치가 기본 브랜치면 새로 만들 작업 브랜치 이름을 정한다.
- **고치기**: 받은 지시대로 고친 뒤 `run-ticket` 스킬을 불러와 이번 흐름의 변경에 리뷰 단계만 다시 하게 하고, 결과와 새 코드 지문으로 상태 파일 `## 리뷰`를 고친 뒤 이 단계로 돌아온다.
- **멈추기**: 지금 상태와 남은 일을 보고하고 끝낸다.
