# 3단계: 작업 지시서

set-brief의 단계 가운데 입력 수집과 초안 작성은 새 컨텍스트의 서브에이전트 하나에 맡기고, 냉독 검증의 서브에이전트는 이 세션이 직접 띄운다. 저장 위치 선택, 사용자 확인, 게시도 이 세션이 직접 한다. 에이전트 규칙이 brief 초안을 맡을 에이전트를 정해 두었으면 그 에이전트로 띄운다. 구체화 기록이 상태 파일에 있으므로 서브에이전트는 대화 없이 초안을 쓸 수 있다. 서브에이전트를 띄울 수 없으면 같은 세션에서 차례로 한다.

초안을 쓰는 서브에이전트에 냉독 검증까지 맡기지 않는다. 서브에이전트가 안에서 다시 서브에이전트를 띄우고 기다리면, 멈춰도 이 세션이 알아차리지 못한다. 초안과 검증이 한 보고에 섞이면 어느 문장이 검증을 거쳤는지도 가릴 수 없다.

## 1. 저장 위치

set-brief의 "저장 위치 선택"은 직접 묻는다.

상태 파일 `- brief 초안:`에 적힌 파일이 남아 있으면 이어 가는 흐름이다. 2번을 건너뛴다. `- brief 냉독 결과:` 파일도 남아 있으면 3번을 건너뛰고 4번에서 그 내용을 냉독 검증 결과로 쓴다. 그 파일이 없으면 3번부터 한다.

## 2. 초안 맡기기

서브에이전트에 set-brief의 "입력 수집"과 "초안 작성"을 맡긴다.

넘길 것:

- set-brief 스킬 이름
- 상태 파일 경로. `## 구체화 기록`이 합의한 내용이다
- 구체화를 확정한 뒤에 바꾼 파일과 커밋
- 고른 저장 위치
- 초안을 쓸 저장소 밖 임시 파일 경로

사용자에게 물어야 할 일(목적이 여럿인 경우 등)은 묻지 말고 돌려 달라고 한다. 냉독 검증은 하지 말고 초안만 쓰라고 한다.

돌려받을 것: 임시 파일 경로, 돌려준 질문.

돌려받으면 바로 임시 파일 경로를 상태 파일 `- brief 초안:`에 적는다.

## 3. 냉독 검증

set-brief의 "냉독 검증"을 이 세션이 직접 한다. 서브에이전트 3개를 이 세션이 띄우고, 답을 비교해 임시 파일의 초안을 고친다. 에이전트 규칙이 냉독 검증을 맡을 에이전트를 정해 두었으면 그 에이전트로 띄운다. 합의한 내용은 상태 파일의 `## 구체화 기록`이다.

끝나면 바로 냉독 검증에서 고친 항목, 남은 어긋남, 2번에서 돌려받은 질문을 초안과 같은 폴더의 `<초안 파일 이름>.review.md`에 저장하고 그 경로를 `- brief 냉독 결과:`에 적는다. 초안만 남고 이 결과가 사라지면, 이어 갈 때 사용자가 남은 어긋남을 보지 못한 채 게시한다.

## 4. 확인과 게시

초안과 냉독 검증 결과로 set-brief의 "사용자 확인"과 "게시와 인덱스 갱신"을 직접 한다. 본문은 임시 파일을 그대로 쓴다. docs면 그 파일을 옮기고, 이슈면 `--body-file`로 넘긴다. 수정 요청은 임시 파일을 고쳐 반영한다.

게시한 뒤 냉독 결과 파일을 지우고 `- brief 초안:`과 `- brief 냉독 결과:` 값을 지운다.
