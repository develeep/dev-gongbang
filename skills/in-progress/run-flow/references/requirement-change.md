# 요구사항이 바뀌었을 때

진행 중인 흐름의 기획서나 요구사항이 바뀌면 새 흐름을 만들지 않고 같은 상태 파일에서 1단계로 돌아간다. 결정, 답변, 리뷰 기록이 한 파일에 이어져야 무엇이 왜 바뀌었는지 남는다.

1. **상태 파일**: `- 현재 단계:`를 1단계로 고친다. `## 단계`에서 다시 할 단계의 체크를 풀고 `(YYYY-MM-DD 요구사항 변경으로 다시 함)`을 붙인다. 다시 한 단계를 마치면 체크하고 같은 표시를 남긴다.
2. **1단계**: 이전 요구사항 문서는 `<이름>-<이전 날짜>.md`로 옮기고, 새 문서를 원래 경로에 쓴다. 새 문서 맨 위에 이전 판 링크를 둔다. 받은 답은 `## 요구사항 답변`에 날짜를 붙여 더한다.
3. **2단계**: 이전 구체화 기록에서 바뀌거나 새로 생긴 칸만 묻고 확정한다. 나머지 칸은 유지한다고 알린다.
4. **3단계**: 기존 brief를 고칠지 새 brief를 쓸지 묻는다. 고치면 `- 작성일:`은 두고 `- 수정일:` 줄을 더하며, 끝난 티켓 링크와 완료 기록은 남긴다.
5. **4단계**: 끝난 티켓은 그대로 두고 남은 일만 다시 나눈다. 버린 방식으로 쓰인 티켓은 다시 쓴다.
