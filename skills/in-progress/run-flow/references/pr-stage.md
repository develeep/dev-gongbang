# 7단계: PR 만들기

1. run-flow 6단계에서 정한 대로 작업 브랜치를 만들고 커밋한다. 커밋한 뒤 `git status --porcelain`이 비었는지 확인하고, 남은 변경이 있으면 보여 주고 커밋에 넣을지 묻는다.
2. PR 본문을 이 세션이 직접 쓴다. 입력은 brief, `git diff --stat <기본 브랜치>...HEAD` 출력, 티켓의 `## 완료 기록`, 상태 파일의 `## 리뷰`다. diff 전문은 읽지 않고 필요한 파일만 읽는다. 큰 diff는 컨텍스트에 다 들어가지 않는다. 바꾼 이유, 바꾼 내용, 확인 방법 순서로 쓰고, 레포에 PR 템플릿(`.github/pull_request_template.md` 등)이 있으면 그 형식을 따른다. 확인 방법에는 brief의 "확인 기준"과 완료 기록의 "확인한 것"을 옮긴다. 교차 리뷰를 대체했으면(`## 리뷰`의 `- 교차 리뷰 모델:`이나 완료 기록의 대체 표시) 그 표시와 수행한 모델을 확인 방법에 그대로 옮긴다. 대체 리뷰는 다른 회사 모델의 독립 검증이 아니므로, PR을 보는 사람이 그 사실을 알아야 한다.
3. 쓴 본문을 보여 주고 확인받는다. 수정 요청은 반영해 다시 보여 준다. 본문은 PR에 공개되고 `## 리뷰`의 고치지 않은 지적, 건너뛴 리뷰, 교차 리뷰 대체 표시가 빠지기 쉬우므로, 확인받기 전에는 push하지 않는다.
4. `git push -u origin <브랜치>`로 올리고, 본문을 임시 파일에 저장해 `gh pr create --base <기본 브랜치> --title "<제목>" --body-file <임시 파일>`로 PR을 만든 뒤 임시 파일을 지운다. 제목은 레포 규칙이 정한 형식을 따르고, 없으면 brief 제목을 쓴다. github.com 원격이 없거나 `gh auth status`가 실패하면 PR 본문을 보여 주고 멈춘다.
5. 한 메시지로 보고한다. 단계별 결과물(요구사항 문서, brief, 티켓, 커밋), PR URL, 고치지 않은 리뷰 지적, 머지는 사용자가 한다는 안내.
