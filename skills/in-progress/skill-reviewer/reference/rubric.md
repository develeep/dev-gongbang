# 판단 검사 루브릭

스크립트가 볼 수 없는 품질 항목이다. 항목마다 **통과 / 미흡 / 해당 없음**으로 판정하고, 미흡이면 근거가 되는 원문을 `파일:줄`과 함께 짧게 인용한다. 인용할 원문이 없으면 미흡으로 판정하지 않는다.

## 목차
- description
- 본문
- 참조 파일과 스크립트
- 범위와 안전

## description

- **L1 무엇과 언제**: 하는 일과 쓰는 상황이 모두 드러나고, 핵심 용도가 앞쪽에 있다. CC는 description이 길면 뒷부분부터 자르기 때문이다.
- **L2 Model-invoked 트리거** (Model-invoked일 때만): 트리거가 구현이 아니라 사용자 의도 기준이고, 도메인 이름을 직접 말하지 않는 요청도 덮으며, 비슷하지만 다른 요청(near-miss)과의 경계가 있다. Claude는 스킬을 덜 쓰는 쪽으로 기울기 때문에 트리거는 약간 적극적으로 쓴다.
- **L3 User-invoked 요약** (User-invoked일 때만): 사람이 읽는 한 줄 요약이고 "~할 때 사용", "Use when" 같은 트리거 문구가 없다. `disable-model-invocation: true`면 description이 모델 컨텍스트에 들어가지 않으므로 트리거 문구는 쓸모가 없다.

## 본문

- **L4 간결성**: Claude가 이미 아는 일반 설명이 없다. 문단마다 "이 지시가 없으면 Claude가 틀릴까?"를 묻고, 아니면 미흡이다.
- **L5 자유도**: 실수하면 위험하거나 순서가 고정된 단계는 정확한 명령으로, 판단이 필요한 단계는 휴리스틱으로 쓰여 있다.
- **L6 기본값**: 방법을 메뉴처럼 나열하지 않고 기본값 하나와 예외 경로 하나를 준다.
- **L7 검증 루프**: 여러 단계로 된 작업에 복사해 쓸 체크리스트와 "검증 → 수정 → 반복" 루프가 있다. 단계가 하나뿐인 스킬은 해당 없음.
- **L8 용어 일관성**: 한 개념을 한 용어로만 부른다.
- **L9 구체적 예시**: 형식이 중요한 출력에는 입출력 예시가 있다. 추상적인 설명만 있으면 미흡이다.
- **L10 이유**: 규칙에 이유가 붙어 있다. 대문자 강조(MUST, NEVER)로 이유를 대신하면 미흡이다.
- **L11 Gotchas**: 직관과 다른 환경 사실(이 저장소만의 규칙, 도구의 함정)이 참조 파일이 아니라 SKILL.md 본문에 있다. 스킬 파일은 이후 턴에 다시 읽히지 않으므로 중요한 함정은 처음 읽는 본문에 있어야 한다.

## 참조 파일과 스크립트

- **L12 읽는 조건**: SKILL.md가 참조 파일마다 언제 읽을지 조건을 적었다. "자세한 내용은 reference/ 참고"처럼 조건이 없으면 미흡이다.
- **L13 스크립트 용도**: 스크립트마다 실행할 것인지 읽을 것인지, 필요한 패키지가 무엇인지 적혀 있다.
- **L14 스크립트 동작**: 스크립트가 대화형 입력을 받지 않고, `--help`와 구체적인 오류 메시지가 있으며, 데이터는 stdout, 진단은 stderr로 낸다. 스크립트가 없으면 해당 없음.

## 범위와 안전

- **L15 범위**: 스킬이 하나의 일관된 작업 단위다. 서로 무관한 작업 둘 이상을 묶었거나, 단독으로 쓸 수 없을 만큼 좁으면 미흡이다.
- **L16 보안**: 목적과 맞지 않는 네트워크 호출, 외부 URL fetch, 스킬 폴더나 작업 대상 밖의 파일 접근이 없다.
