# Set Brief

대화에서 확정한 내용을 이슈나 문서 하나로 옮긴다. 이 기록을 읽는 사람은 대화를 보지 못한 작업자나 다른 에이전트다. 기록만 읽고 작업해도 대화 맥락을 가진 에이전트와 같은 결과가 나와야 한다.

## 핵심 규칙

1. **확인된 사실과 합의한 내용만 적는다.** 추측, 추천, 가설은 "미확인·위험" 섹션에만 둔다. 읽는 사람은 사실과 추측을 구분할 수 없으면 추측을 사실로 따른다.
2. **대화를 가리키는 표현을 쓰지 않는다.** "아까 말한", "위의 방식", "그 파일" 대신 이름, 경로, 값을 직접 적는다. 읽는 사람에게는 대화가 없다.
3. **기준 없는 표현은 수치, 명령, 경로로 바꾼다.** "빠르게", "깔끔하게", "적절히"처럼 해석이 갈리는 말은 대화에서 합의한 기준으로 바꾼다. 기준이 대화에 없으면 그 표현을 "미확인·위험"으로 옮긴다.
4. **사실마다 출처를 붙인다.** 커밋 해시, URL, 또는 "사용자 합의". 경로는 문서 맨 위의 기준 커밋 시점 기준이다.
5. **확인 기준은 외부에서 관찰할 수 있는 동작으로 쓴다.** 실행할 명령과 기대 결과, 또는 사용자가 볼 수 있는 변화로 적는다. 구현 방식에 묶지 않아야 다른 방식으로 구현한 작업자도 같은 기준으로 판정할 수 있다.

## 단계

아래 체크리스트를 시작할 때 한 번 보여 주고, 단계를 마칠 때마다 갱신한다.

```
기록 진행:
- [ ] 1. 입력 수집
- [ ] 2. 저장 위치 선택
- [ ] 3. 초안 작성
- [ ] 4. 냉독 검증
- [ ] 5. 사용자 확인
- [ ] 6. 게시와 인덱스 갱신
```

### 1. 입력 수집

- 대화에 framing-problems로 확정한 구체화 기록이 있으면 그 기록을 기준으로 삼는다. 이후에 한 작업(바꾼 파일, 커밋, 새로 합의한 결정)도 함께 모은다.
- 구체화 기록이 없으면 대화 전체에서 확인된 사실과 합의한 결정만 모은다.

### 2. 저장 위치 선택

`git remote -v`에 github.com이 있고 `gh auth status`가 성공하면 GitHub 이슈를 추천하고, 아니면 docs 문서를 추천한다. 추천을 첫 선택지에 두고 사용자에게 고르게 한다.

docs 문서는 `docs/context/`에 둔다. 레포 규칙(예: 이슈 트래커 문서)이 작업 문서용 디렉터리를 따로 정해 두었으면 그 디렉터리도 선택지로 보여 준다. 어느 디렉터리를 고르든 파일 이름과 인덱스는 6단계 규칙을 따르고, 레포 규칙의 파일 이름(`spec.md` 등)은 쓰지 않는다. 같은 디렉터리에서 다른 형식의 문서와 섞이면 다음 세션이 지난 작업을 고를 수 있다.

### 3. 초안 작성

아래 "기록 템플릿"으로 쓴다. 구체화 기록의 칸은 템플릿의 "가져올 칸"대로 옮긴다. 이슈 제목과 문서 제목은 같은 문장이며, "최종 목적"을 한 줄로 쓴 것이다. 템플릿의 `## ` 섹션 이름, "남은 일"·"바꾸지 않는 범위"·"바꿀 수 없는 조건" 같은 줄 이름, `- 작성일: YYYY-MM-DD` 줄은 글자 그대로 쓴다. 굵게 하거나 이름을 바꾸지 않는다. set-ticket과 run-ticket이 `^- 작성일: ` 정규식과 이 이름들로 brief를 찾고 읽으므로, 바뀌면 다음 세션이 brief를 찾지 못한다.

최종 목적을 한 줄로 쓸 수 없으면 목적이 여럿인 것이다. 초안을 쓰기 전에 목적마다 기록을 나눌지 사용자에게 묻는다. 기록 하나에 목적이 여럿이면 작업자가 범위와 완료 시점을 다르게 잡는다.

내용이 없는 섹션과 줄은 지운다. 빈 칸은 읽는 부담만 늘린다.

### 4. 냉독 검증

Agent 도구로 서브에이전트 3개를 한 메시지에서 병렬로 띄운다. 읽는 사람이 하나면 해석이 갈리는 문장을 찾지 못한다. 대화 내용은 주지 않고 초안 전문과 저장소 경로만 준다. 셋 모두 다음 프롬프트를 쓴다.

```
아래 문서만 근거로, 이 저장소에서 작업을 맡았다고 가정하고 답하라. 코드는 읽어도 되지만 수정하지 마라.
1. 가장 먼저 할 작업과 시작 위치
2. 바꿀 범위와 바꾸지 않을 범위
3. 하지 않을 것
4. 끝났다고 판정하는 방법
5. 문서만으로는 정할 수 없어서 질문하거나 추측해야 하는 것
<문서>
{{초안 전문}}
</문서>
```

각 답을 대화에서 합의한 내용과 비교하고, 세 답끼리도 비교한다. 합의와 어긋난 답, 서브에이전트끼리 갈린 답, 5번의 항목마다 초안의 원인 문장을 고친다. 합의가 없어서 고칠 수 없는 항목은 "미확인·위험"으로 옮긴다. 고친 초안으로 한 번 더 검증한다. 두 번째에도 어긋나는 항목은 고치지 않고 5단계에서 사용자에게 보여 준다.

Agent 도구가 없으면 이 단계를 건너뛰고, 5단계에서 냉독 검증을 하지 못했다고 알린다.

### 5. 사용자 확인

한 메시지에 다음을 보여 준다.

1. 초안 전문
2. 냉독 검증에서 고친 항목과 남은 어긋남
3. 실행할 외부 작업: 이슈를 만들 저장소와 공개 여부(`gh repo view --json visibility`), 붙일 라벨, `context` 라벨이 없으면 새로 만든다는 사실. docs면 저장할 경로.

공개 저장소면 초안에 비밀값, 내부 URL, 개인 정보가 없는지 확인을 요청한다. 이슈는 게시하면 되돌려도 캐시나 알림으로 남는다. 사용자가 맞다고 하기 전에는 6단계로 가지 않는다. 수정 요청을 받으면 반영한 초안을 다시 보여 준다.

### 6. 게시와 인덱스 갱신

**GitHub 이슈**

1. 본문을 임시 파일에 저장한다.
2. `gh label list --search context`에 `context`가 없으면 `gh label create context --description "맥락 파악서 겸 작업 지시서"`로 만든다.
3. `gh issue create --title "<제목>" --body-file <임시 파일> --label context`
4. 이슈 URL을 알리고 임시 파일을 지운다. 이 라벨이 인덱스 역할을 한다. 다음 세션은 `gh issue list --label context`로 목록을 본다.

**docs 문서**

1. 2단계에서 고른 디렉터리(기본 `docs/context/`)에 `YYYY-MM-DD-<slug>.md`로 저장한다. slug는 제목을 영문 소문자와 하이픈으로 줄인 것이다. 같은 이름의 파일이 있으면 덮어쓰기 전에 묻는다.
2. 같은 디렉터리의 `README.md`에 한 줄을 추가한다: `- [YYYY-MM-DD 제목](./YYYY-MM-DD-<slug>.md): 요약 문장`. 파일이 없으면 `# Context` 제목과 함께 만든다. 디렉터리가 `docs/context/`가 아니어도 만든다.
3. 저장한 파일 목록을 알린다. 커밋은 하지 않는다.

**티켓 분할 안내**

게시를 마친 뒤 "남은 일"이 새 컨텍스트 창 하나로 끝나지 않을 크기로 보이면, `/set-ticket`으로 작은 티켓으로 나누라고 사용자에게 안내한다. 한 창으로 끝날 크기면 새 세션에서 `/run-ticket <brief 경로나 이슈 번호>`로 실행하라고 안내한다. 두 스킬 모두 User-invoked라 이 스킬에서 호출할 수 없다.

## 기록 템플릿

```markdown
# <최종 목적 한 줄>

- 기준 커밋: `<해시>`
- 작성일: YYYY-MM-DD

## 요약
<이슈 요약>

## 배경·의도
<왜 하는지, 계기. 가져올 칸: R1 의도, R1 계기>

## 최종 목적
<완료됐을 때 관찰할 수 있는 상태. 가져올 칸: R2 이상, R5 목표>

## 확인된 사실
- <사실>
<가져올 칸: R2 현재, R2 문제, R2 원인 중 "확인됨", R3 자원>

## 합의한 작업
- 해법: <가져올 칸: R5 해법>
- 해법 근거: <근거>: <출처> (가져올 칸: R4 근거 중 "맞음"·"조건부". "조건부"는 조건도 적는다. 출처가 "모델 지식, 미검증"이면 "미확인·위험"으로 옮긴다)
- 완료한 일: <파일, 커밋>
- 남은 일:
  - [ ] <작업>

## 작업 경계
- 바꾸는 범위: <파일, 모듈, 동작>
- 바꾸지 않는 범위: <파일, 모듈, 동작>
- 바꿀 수 없는 조건: <가져올 칸: R3 제약>

## 하면 안 되는 것
- <행동>: <이유>

## 확인 기준
- [ ] `<명령>` → <기대 결과>
- [ ] <사용자가 관찰할 수 있는 변화>

## 미확인·위험
- <가설인 원인, 확인 방법> (가져올 칸: R2 원인 중 "가설")
- <부작용: 감수 / 완화책> (가져올 칸: R6 부작용)
- <장애물> (가져올 칸: R6 장애물)
```
