# Set Guidelines

레포의 언어와 프레임워크를 파악하고, [awesome-guidelines](https://github.com/Kristories/awesome-guidelines)에 실린 가이드 중 사용자가 고른 것의 원문을 읽어 규칙을 뽑는다. 뽑은 규칙으로 분야별 규칙 파일(`.claude/rules/<분야>.md`), CLAUDE.md/AGENTS.md, 린터·포매터 설정을 만든다. 무엇을 만들고 어디에 쓸지는 사용자가 고르고, 파일은 최종 승인을 받은 뒤에만 쓴다.

## 주의할 점

- 링크가 깨져 있거나 원문을 읽을 수 없는 가이드는 건너뛴다.
- 고른 가이드끼리 규칙이 충돌하면 충돌하는 규칙을 나란히 보여 주고 사용자가 하나를 고르게 한다. 어느 쪽이 맞는지는 팀의 선호라서 가이드만 보고 정할 수 없기 때문이다.
- 팀 규칙은 가이드에서 뽑은 규칙보다 우선한다. 가이드는 일반론이고 팀 규칙은 이 레포에서 이미 합의한 결정이기 때문이다. 팀 규칙은 레포에 이미 있는 규칙(컨벤션 문서, CLAUDE.md/AGENTS.md, `.claude/rules/`, 린터·포매터 설정)과, 산출물을 만든 뒤 사용자가 CLAUDE.md/AGENTS.md의 "팀 규칙" 절에 추가하는 규칙이다. 사용자가 초기화를 고른 레포에서는 기존 규칙을 우선순위 대상에서 뺀다.
- CLAUDE.md/AGENTS.md는 세션마다 컨텍스트에 올라가므로 커지지 않게 쓴다. 핵심 규칙만 두고 세부는 규칙 파일로 옮긴다. 린터·포매터가 강제하는 규칙은 다시 적지 않는다.
- 규칙 파일은 `paths`를 적었을 때만 맞는 파일을 다룰 때 로드되고, `paths`가 없으면 CLAUDE.md처럼 세션마다 로드된다. 특정 파일에만 해당하는 분야는 `paths`에 그 파일 패턴을 적는다.
- CLAUDE.md와 AGENTS.md가 둘 다 있으면 Claude Code는 CLAUDE.md만 읽는다. 둘 다 만들면 CLAUDE.md에 `@AGENTS.md` 줄을 넣어 AGENTS.md를 불러온다.
- 산출물 파일에는 출처 표시, 링크, 템플릿에 없는 절(가이드와 다르게 한 이유, 적용하지 않은 규칙 등)을 넣지 않는다.

## 워크플로

아래 체크리스트를 첫 응답에 보여 주고, 단계가 바뀔 때 갱신한다.

```
진행 상황:
- [ ] 1. 레포 파악과 확인
- [ ] 2. 기존 규칙 처리 방식 결정 (기존 규칙이 있을 때)
- [ ] 3. 가이드·도구 추천과 선택
- [ ] 4. 원문 읽기와 규칙 추출
- [ ] 5. 산출물 선택과 최종 승인
- [ ] 6. 작성
```

### 1. 레포 파악과 확인

레포를 살펴 언어와 프레임워크를 정하고, 사용자에게 맞는지 확인받는다. 레포에 이미 있는 컨벤션 문서, CLAUDE.md/AGENTS.md, `.claude/rules/`, 린터·포매터 설정도 함께 찾는다.

### 2. 기존 규칙 처리 방식 결정

1단계에서 기존 규칙을 찾았으면 진행 방식을 사용자가 고르게 한다.

- **개선·추가**: 기존 규칙을 유지하고, 고칠 점과 더할 규칙을 추천한다.
- **초기화**: 기존 규칙을 걷어 내고 새로 정한다.

### 3. 가이드·도구 추천과 선택

`reference/guides-index.md`에서 1단계에서 확인한 언어, 프레임워크, 플랫폼, 도구에 해당하는 절을 찾아 가이드와 린터·포매터를 추천하고 사용자가 고르게 한다. 목록에 그 언어의 린터·포매터가 없으면 그 언어에서 널리 쓰는 도구를 추천하되 "awesome-guidelines 목록 밖"이라고 표시한다.

### 4. 원문 읽기와 규칙 추출

고른 가이드의 원문을 읽어 이 레포에 적용할 규칙을 뽑는다.

- 가이드 규칙이 팀 규칙과 다르면 팀 규칙을 따른다.
- 아키텍처 규칙은 고른 가이드에 아키텍처를 다루는 내용이 있을 때만 뽑는다. 없으면 아키텍처 규칙 파일을 만들지 않는다. API 설계 규칙은 아키텍처가 아니라 분야 규칙으로 다룬다.

### 5. 산출물 선택과 최종 승인

사용자가 만들 산출물과 레포에 맞는 경로를 고르게 한다.

- 분야별 규칙 파일: `.claude/rules/<분야>.md`, `templates/rule.md` 양식
- CLAUDE.md / AGENTS.md: `templates/agent-instructions.md` 양식
- 린터·포매터 설정: 고른 도구의 문서를 따른다

만들거나 바꾸거나 지울 파일 목록과 내용 요약을 보여 주고 최종 승인을 받는다. 규칙 파일마다 `paths` 패턴도 목록에 적는다.

### 6. 작성

승인받은 파일만 쓴다. 린터·포매터 설정을 만들었으면 그 도구를 실행해 설정이 오류 없이 읽히는지 확인한다. 오류가 나면 고치고 다시 실행한다. 도구가 설치돼 있지 않으면 설치해서 확인할지 사용자에게 묻는다.

## 참조 파일

- `reference/guides-index.md`: 3단계에서 추천할 가이드와 도구를 찾을 때 읽는다. awesome-guidelines README의 스냅샷이다.
- `templates/rule.md`: 5단계에서 사용자가 규칙 파일을 고르면 읽는다.
- `templates/agent-instructions.md`: 5단계에서 사용자가 CLAUDE.md나 AGENTS.md를 고르면 읽는다.
