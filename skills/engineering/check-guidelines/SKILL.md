# Check Guidelines

레포에 있는 규칙으로 코드를 검사한다. 규칙은 `.claude/rules/` 규칙 파일, CLAUDE.md/AGENTS.md, 린터·포매터 설정에서 모은다. 위반을 규칙별로 묶어 보고하고, 사용자가 고른 위반만 고친 뒤 다시 검사해 확인한다.

## 주의할 점

- 규칙 파일, CLAUDE.md/AGENTS.md, 린터·포매터 설정이 하나도 없으면 검사하지 않고, `/set-guidelines`를 실행해 규칙부터 만들라고 안내한다.
- `paths`가 있는 규칙 파일은 그 패턴에 맞는 파일에만 적용한다. `paths`가 없는 규칙 파일과 CLAUDE.md/AGENTS.md는 모든 대상 파일에 적용한다.
- 규칙끼리 충돌하면 보고서의 "규칙 충돌"에 충돌하는 규칙과 그 위치를 적고, 규칙을 어떻게 고칠지 제안한다. 어느 규칙이 맞는지는 팀이 정할 일이라 검사하는 쪽에서 고를 수 없기 때문이다.
- 위반인지 판단하기 어려우면 위반으로 세지 않고 보고서의 "애매함"에 애매한 이유와 함께 적는다. 위반으로 세면 사용자가 문제없는 코드를 고치게 될 수 있기 때문이다.
- 린터·포매터가 설치돼 있지 않으면 설치하지 않고 건너뛴다. 보고서 요약의 "검사 못 함"에 그 도구를 적는다.

## 워크플로

아래 체크리스트를 첫 응답에 보여 주고, 단계가 바뀔 때 갱신한다.

```
진행 상황:
- [ ] 1. 검사 범위 정하기
- [ ] 2. 규칙 모으기
- [ ] 3. 검사
- [ ] 4. 보고
- [ ] 5. 고치기와 재검사 (사용자가 고칠 때)
```

### 1. 검사 범위 정하기

인자로 범위를 받는다. 인자가 없으면 아래 넷 중 하나를 고르게 한다.

- `all`: 레포 전체
- `diff`: 커밋하지 않은 변경 전부. staged, unstaged, 새 파일(untracked)을 모두 넣는다.
- `branch`: origin의 기본 브랜치와 갈라진 지점부터 지금까지 바뀐 파일. 기본 브랜치를 찾지 못하면 기준 브랜치를 묻는다.
- 경로: 사용자가 지정한 파일이나 디렉터리

### 2. 규칙 모으기

`.claude/rules/`, CLAUDE.md/AGENTS.md, 린터·포매터 설정을 찾아 읽는다. 규칙 파일마다 `paths`를 확인해 대상 파일 중 어디에 적용되는지 정한다.

### 3. 검사

- 규칙 파일과 CLAUDE.md/AGENTS.md의 규칙은 대상 파일을 읽어 판단한다.
- 린터·포매터는 설치된 것만 대상 파일에 실행하고 결과를 위반에 넣는다.

대상 파일이 100개를 넘으면 오래 걸리고 컨텍스트를 많이 쓴다고 경고한다. 파일 수와, 최상위 디렉터리별로 나눈 구역을 보여 주고 승인을 받는다. 승인받으면 구역마다 서브에이전트를 하나씩 띄워 검사하고 결과를 합친다.

### 4. 보고

`templates/report.md` 양식으로 보고한다. 위반 번호는 보고서 전체에서 이어 매긴다. 보고한 뒤 고칠지 묻고, 고친다면 고칠 위반을 번호로 고르게 한다.

### 5. 고치기와 재검사

고른 위반만 고친다. 고친 파일을 같은 규칙으로 다시 검사해 고른 위반이 없어졌는지 확인한다. 남아 있으면 고치고 다시 검사한다. 끝나면 고친 위반과 재검사 결과를 알린다.

## 참조 파일

- `templates/report.md`: 4단계에서 보고서를 쓸 때 읽는다.
